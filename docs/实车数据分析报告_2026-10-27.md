## 二、分组逐项分析

### 1.csv —— 移动 + 部分旋转（61.0s，循环 82Hz）

**检测**：95.5% 帧有板，平均 0.99 块，置信度 0.943。有 4.5% 的帧丢板，是移动中最值得关注的一点。

**PnP 重投影误差：2.63px（p50 2.65 / p95 5.20 / max 5.99）**
- 分块看（每 500 帧≈6s）：`>3px` 比例从 2.6% 一路爬到 **78.4%**（帧 2500–3000），之后回落到 30–45%
- 这个 78.4% 的块是全组最差区间，PnP 均值 4.17px
- 对照静止组 100% 的帧都 <1px，说明**不是标定问题，是运动模糊/目标快速移动时检测角点抖动**
- 顶点速度估计只有 0.13 m/s（p95 0.43），速度本身不高，但对小目标（板宽 0.135m）来说，几像素的角点抖动就被 PnP 放大

**半径漂移（最需要修的）：**
```
帧    0: 0.2069      帧 1500: 0.2066      帧 3000: 0.2260
帧 2000: 0.2091      帧 2500: 0.2180      帧 4500: 0.2230
```
前 1500 帧（约 18s）稳定在 0.2066–0.2070，之后**单调爬升到 0.2260 并稳定在那里，没有回来**。这是 2.6cm 的永久性偏差（真实 R 应该是 0.2 左右，22.6cm 明显偏大）。

**EKF 距离**：偏差均值 -0.03cm（无系统偏置），但 **std 5.22cm、p95|.| 9.82cm** —— 意味着有相当一部分帧距离估计偏离观测近 10cm。

**ω**：p50 0.05 rad/s、p90 0.78、max 3.59。88.2% 的时间接近静止，8.6% 在 1–3 rad/s。两处相邻帧 ω 突变（帧 1087：+0.00→-3.23→-0.94），是 2 帧的瞬时毛刺，已被 EKF 快速纠正，不是持续问题。

### 2.csv —— 正弦旋转 + 高速旋转（63.5s，循环 79Hz）

正弦周期约 **0.97s**（ω 过零 94 次，平均间隔 0.49s），峰值 **|ω| = 9.31 rad/s**。峰值角加速度约 `9.31 × 2π/0.97 ≈ 60 rad/s²`，这个激励相当剧烈。

**检测**：100%，置信度 0.938。有一帧 `detection_id` 出现 5（其他全为 3），但 `target_id` 全程 3，说明**身份后验成功拒绝了这一次误检**，符合预期。

**PnP 误差 1.72px**，反而比 1.csv 的移动段好。分 ω 档看：
| \|ω\| | PnP 均值 | >3px 占比 |
|---|---|---|
| <1 | 1.90px | 4.5% |
| 1–3 | 1.54px | 21.1% |
| 3–5 | 1.66px | 24.6% |
| >5 | 1.63px | 22.2% |

PnP 均值不随 ω 变差，但 `>3px` 比例在高速段稳定在 22–25%（低速段只有 4.5%）——高速时总有一部分帧角点质量下降。

**EKF 距离（本组最突出的问题）：系统性偏大 +6.12cm，std 10.91cm，p95 25.75cm**

分块趋势：
```
帧    0:  +7.58cm      帧 2000: +10.16cm     帧 4000: +13.01cm
帧 1000:  +2.99cm      帧 3000:  +9.88cm      帧 4500:  +1.83cm
```
**偏置是正的且持续存在**（10 个块里 9 个为正，均值 +6.1cm）。方向上，EKF 认为车比实测**更远** 6cm。这会直接影响 pitch 补偿和距离相关的提前量。std 10.9cm 说明在正弦换向的最剧烈处（角加速度最大）EKF 跟不上观测的变化，出现"甩尾"。

**ω 跟踪**：p50 3.76、p90 7.37、max 9.31 rad/s。相邻帧 ω 变化 p50 0.031、p90 0.30、max 3.33（仅 1 次，帧 2291：+6.32→+2.99）。**在峰值 9.3 rad/s 的正弦激励下 ω 跟踪是干净的**，符号翻转 0 次误翻——**这部分表现很好，不建议动 ω 相关参数**。

**半径**：恒定 0.2854，5000 帧无一丝变化。这个 0.2854 与 1.csv 初始的 0.207 差 7.8cm，与 3.csv 相同。**说明这台"车"的半径真值在 0.28 附近**，那么 1.csv 从 0.207 漂到 0.226 就更可疑了——它连初始值都没收敛到真值。

**EKF 状态**：99.5% 稳定，7 次短时不稳定（每次 0.01–0.08s），都在正弦换向附近。属于可接受的瞬时抖动。

## 三、根因判断

### 问题 A：半径在移动段漂移 2.6cm 且不回退（优先级：高）

**现象**：1.csv 从 0.207 漂到 0.226 后锁死；2/3.csv 完全冻结在 0.2854。
**判断**：半径更新在"移动"场景下被污染——很可能是 PnP 距离误差（移动段 p95 9.8cm）通过 `updateRadiusFromPairs` 这类基于观测几何关系的路径渗进R，而且**更新是单向棘轮式的**（只往大改，不回来）。2/3.csv 半径一动不动、连初始收敛都没有，说明半径在那种场景下**根本没被更新**（或者更新量小于输出精度）。
**影响**：R 偏 2.6cm → 相位→板位置的映射整体偏移 → 提前量算错。**这是最该先修/先调的。**

### 问题 B：旋转段距离系统性偏大 +6.1cm（优先级：高）

**现象**：正弦旋转段，EKF 距离比 PnP 观测大 6cm，且 90% 的时段都是正的。
**判断**：`ekf_x`/`ekf_y` 的位置估计在旋转激励下滞后或偏差。注意 PnP 本身在旋转段误差只有 1.7px（比移动段好），所以**不能怪观测**，是 EKF 的位置/速度通道跟不上，或者初始化/收敛后的偏置没被修正。
**影响**：距离就是提前量的分母，6cm 在 2m 距离上是 3% 的量级误差，加上 std 10.9cm，命中率会掉。

### 问题 C：移动段 PnP 误差恶化到 2.63px（优先级：中）

**现象**：某一 6s 区间 `>3px` 占比 78.4%。
**判断**：移动时的运动模糊 + 检测角点抖动。这不是滤波器能修的，属于检测/解算层。
**影响**：喂给 EKF 的观测质量下降，是问题 A/B 的上游诱因。

### 问题 D：移动段丢板 4.5%（优先级：中低）

1.csv 有 4.5% 的帧检测不到板。可能和运动模糊、曝光、或检测器阈值有关。

## 四、调参建议（按顺序执行，一次只改一项）

### 第 0 步：先确认半径这个根本问题

在动手调 Q/P 之前，先回答一个问题：**这台车的真实轮距半径到底是多少？**
- 如果真值 ≈ 0.28（2/3.csv 的值），那 1.csv 从 0.207 起跳本身就是错的 → 半径初值/收敛逻辑有问题，**不是调参能解决的，需要改代码**
- 如果真值 ≈ 0.20–0.21，那 2/3.csv 卡在 0.2854 就是错的 → 半径先验/更新被冻结

**这一步必须先做**，否则后面所有 Q/P 调参都在错误基准上。

---

### 第 1 步：修旋转段距离偏差 → 调位置过程噪声

**文件**：`student/src/RotatingArmorTracker.cpp` 的 `applyProcessNoise()`，参数 `config_.ekf.process_accel_scale`

**依据**：旋转段 EKF 距离**滞后/偏大**，说明位置通道置信度太高（Q 偏小），EKF 太相信自己的预测。

**动作**：
```bash
# 先在 PC 上用回放验证（不要直接上车）
Q_SCALE=2.0 ./build/test_camera_playback tests/resources/redrotate.avi --red --ekf --headless
```
- 观察「距离残差」是否从 +6cm 降到 ±3cm 以内
- 如果有效，再在车上试 `process_accel_scale = 2.0`
- 若 2.0 仍滞后，试 3.0；若开始出现距离抖动加大（PnP 距离 std 上升），回退一档

**权衡**：Q 调大会让静止时的距离抖动变大（现在静止 p95 1.98cm 很漂亮）。**建议 2.0 封顶**，如果 2.0 不够，说明是结构问题（见第 4 步），不要一味加 Q。

---

### 第 2 步：移动段距离抖动 p95 9.8cm → 下调观测噪声

**参数**：`config_.ekf.position_sigma_m`（默认 0.03）

**依据**：1.csv 距离 std 5.2cm 但均值无偏（-0.03cm），说明**观测本身噪声大**，EKF 在跟噪声跑。移动段 PnP 误差 2.63px（静止 0.57px，涨了 4.6 倍）。

**动作**：把 `position_sigma_m` 从 0.03 提到 **0.045~0.05**，让 EKF 更不信任单帧观测。

**症状对照**：
- 调大后距离变平滑但**更迟钝**（换向时甩得更远）→ 说明 Q 和 R 都在往同方向推，回到第 1 步检查
- 调大后距离平滑且不迟钝 → 正确方向，保留

---

### 第 3 步：静止段的 x 方向速度抖动 → 这是 Q 的边界，先别动

3.csv 里 `ekf_vx` std 0.0123 m/s，是 `vy` 的 15 倍。这是**深度方向的可观测性天然弱**（单目测距靠板宽，x 方向的约束来自板子看起来多大）。这不是参数能根治的，属于问题 D 的结构性限制。

**建议**：如果第 1 步 Q 调到 2.0 后 vx 抖动明显放大，把 Q 回退到 1.5，**接受 x 方向稍慢**，换取静止时不抖。

---

### 第 4 步：如果 1–3 步都解决不了 → 那才是结构问题

需要改代码的方向（**先不动，等你说**）：
1. **半径更新加保护**：移动段 PnP 误差 >2px 的帧不参与半径更新，并加大半径的平滑窗口
2. **距离通道单独处理**：旋转段的距离偏差是正的且稳定，像是某种系统性偏置——可以考虑给 x/y 位置加一个基于多帧的偏置估计
3. 移动段检测：考虑启用更严格的置信度阈值或角点亚像素细化

## 七、已知数据局限（必须说明）

1. **开火结果无法直接评估**：CSV 里没有 `fire_allowance` 字段，只能用 `ekf_state=1 && target_found>0` 作为"可开火窗口"代理。真实命中率需要看回放视频或电气侧反馈。
2. **没有"绝对真值"**：PnP 观测本身在移动段有 2.63px 误差，拿它当参照会低估 EKF 的真实误差。要严谨评估需要靶纸或动捕真值。
3. **`topdown_omega` 不是独立估计**：它直接转发 EKF 的 `yaw_rate`，两路一致性 100% 是必然结果，不能作为互相验证。
4. **按行号对比会错位**：所有指标各 5000 条但写入时刻不同（仅 38% 精确重合），本报告已按时间戳对齐；如果你自己分析请务必对齐。
