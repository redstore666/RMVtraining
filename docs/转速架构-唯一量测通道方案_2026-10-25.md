# 转速架构：把四条半成品通道收敛成一条量测口径（2026-10-25）

结论先说：**当前架构在物理上就不可能把 ω 估对，问题不在参数。** 唯一的修法是
换观测量的使用方式——把 ω 从"逐帧角度残差"改成"窗口相位拟合 + 软量测"。
下面的数字全部来自本轮实测（v4 / `--only-id 3` / 166 fps），不是推演。

---

## 一、目标与验收（先把"什么叫成了"钉死）

用户要的"效果"是**俯视图显示的转速 = 视频实际转速**。俯视图已经改成
`seat = round(φ/90°)`（§四十六），所以等价于：

1. `state(6)` 的相位推进速率 = 真实转速，误差 < 10%；
2. `state(7)` 的 \|ω\| 与独立估计比值落在 0.9~1.1（现有：0.63/1.09 = **0.58**）；
3. 相位单调（现有：正转 1133° / 回转 673°，来回摆 ±130°）；
4. `ekf_tracker` 的 G 组（ω=8 预测）、H 组（静止+噪声法向）不许红。

## 二、定量病根：单帧转速信噪比 0.08

用帧间二阶差分估单帧位置噪声（运动是平滑的，二阶差分只剩噪声）：

| 量 | 实测/推算 |
|---|---|
| 单帧位置噪声 σ | **13.8 mm**（n=639 二阶差分 p50 = 33.9 mm ÷ √6） |
| 真实 1.1 rad/s、R=0.17 m、dt=6.0 ms 下每帧旋转位移 | **1.13 mm** |
| **单帧转速 SNR** | **0.08** |

**一帧里"转"只贡献 1.1 mm，噪声贡献 13.8 mm。** 因此任何形式的"逐帧差分"
（角度差、切向投影、PLL 残差）在数学上都不可能工作——不是调参问题。

窗口最小二乘能救：σ_ω = σ_α / √(Σ(t−t̄)²)，σ_α = 13.8mm/170mm = 0.081 rad。

| 窗口 N（166fps） | 跨度 | σ_ω |
|---|---|---|
| 30 帧 | 0.18 s | 0.28 rad/s |
| **60 帧** | **0.36 s** | **0.10 rad/s** |
| 100 帧 | 0.60 s | 0.047 rad/s |

60 帧窗口把 1.1 rad/s 的量测做到 9% 精度——够用，且这正是
`tools/omega_truth.py` 用 61 帧斜率能稳定给出 1.09 rad/s 的原因
（21 帧窗给出的 p50=3.14 rad/s 全是噪声，同一份数据）。

## 三、现有四条通道为什么全废

代码里已经有四套转速估计，**全部默认关闭**，逐一打开都不解决问题：

| 通道 | 位置 | 失效原因 |
|---|---|---|
| `tangent_rate`（切向投影） | `RotatingArmorTracker.cpp:3550` 附近 | 逐帧量测，SNR 0.08；且 `setRate((1-α)ω+α·meas)` 硬写状态，α=0.25 相当于 4 阶低通，天然滞后 |
| `rate_from_tracklet`（逐帧同板角速度） | `:3308` | 同上逐帧；`sigma_omega = max(0.35, σ_θ/dt)`，dt=6ms 时分母把 σ 推到 5+ rad/s，等于不接受；另有 `|ω|≥3 rad/s` 门 |
| `rate_window`（0.35 s 斜率） | `:4551` | 方向对但三处错：① σ 用 `sigma_fit/span`，正确是 `sigma_fit/√Sxx`，高估 2.2 倍；② 圆心用 `detected_circle_center`（比 EKF 中心更抖）；③ 门是 `|slope|≥0.5`（绝对速度，低速自转被挡） |
| `batch_fit`（(c,R,ω,φ) 联合解） | `:4761` | **R 自由 → 病态**。实测窗口内解出 R=0.008~0.019 m（真值 0.17），ω 一路撞 ±12 clamp；且用 `setRate/rotatePhase/shiftCenter` 硬写，一开 v4 ≤5cm 73.2→48.7、v1 47.0→18.5 |

另有一条 `updateFaceYawForSlot`（角度直接量测），是当前**唯一活着**的相位/转速源，
但 σ=2.5 rad（143°）——等于告诉滤波器"这个量测基本别信"，而且它的 4 折歧义靠
`best_slot` 消解，多板帧身份翻转率 51%，判错就注入 ±90° → 这正是相位来回摆 ±130°
的直接原因（实测正转 1133°/回转 673°）。

> 所以现在的真实运行态是：**ω 唯一的来源是一个被主动调弱、且会 ±90° 跳的量测，
> 而 Q 被钉在 0.01 让它没法动。** 两者叠加 = ω 冻结 + 相位被拽着乱跳。

## 四、为什么"调 Q"这条路走不通（已实测）

`angular_accel` 从 0.01 抬到 1/10/20/40/400：

- v4 ≤5cm：73.15 / 70.47 / 58.39 / 72.89 / 72.48 / 63.49；
- ang_accel=20 时 `ekf_tracker` G 组（ω=8 预测点误差 0.014→0.354 m，命中率 100%→43%）
  与 H 组（静止+噪声法向，ω 0→0.45）双红。

**Q 大 → φ 漂 → 预测准不了；Q 小 → ω 动不了。** 这个矛盾只存在于"ω 不可观测"的前提下。
把 ω 变成**真正的量测**之后，Q 保持 0.01 也能让 φ 以正确速率推进，矛盾自然消失。

## 五、唯一方案：一条观测通道，三段职责

不改状态定义、不加新状态、不动 Q。只做"观测口径 + 融合方式"的替换。

### 第 1 段：观测量 = 窗口相位斜率（R 固定，c 固定）

每帧把"同一块板"的 `(t, p)` 入环形缓冲（同板判据：帧间位移 < 0.10 m，
换板就清空重来——这是局部判据，不依赖身份先验）。每 2~3 帧触发一次：

1. 取最近 `N=60` 个样本（参数 `rate_window_n`，替代 `rate_window_s=0.35`）；
2. 圆心 `c` 用 EKF 当前 `state(0),state(2)`，半径 `R` 用 `state(8)`（**固定，不参与拟合**）；
3. `α_k = atan2(p_k − c)`，逐帧 `fold90` 展开（消掉 4 板歧义，只留相对斜率）；
4. 对 `(t_k, α_k)` 做最小二乘，得 `ω`、`Sxx = Σ(t−t̄)²`、残差 `σ_α`；
5. `σ_ω = σ_α / √Sxx`，下界 0.05。

**为什么必须固定 R**：R 自由时短弧上的 (R, ω) 是病态的（batch_fit 实测解到 R=8 mm）。
R 是已知的机器人尺寸，本来就不该在这一层估。

### 第 2 段：融合 = `updateRate`，不许硬写

`ekf_.updateRate(ω, σ_ω)`。删掉 `setRate` / `rotatePhase` / `shiftCenter` 这类
在 `batch_fit` 里的硬写——它们抹掉协方差，导致"量测对了但滤波器崩了"。

### 第 3 段：门控 = 显著性检验，不是绝对阈值

```
|ω| > 3·σ_ω   → 更新
否则          → 不更新
```

1.1 rad/s（σ_ω=0.10 → 阈值 0.30）和 8 rad/s 用同一条判据；静止时 slope≈0、
σ 覆盖 0 → 自动不更新，H 组契约不必靠 `1.5/3.0 rad/s` 这种场景相关门限保护。
`rate_window_min_rate_rad_s=0.5`、`rate_tracklet_min_rate_rad_s=3.0` 一并删掉。

### 第 4 段：Q 保持 0.01 不动

φ 由 `ω` 传播（`F(6,7)=dt`），不再靠角度残差硬拽；角度量测退回"小残差修正"的角色，
σ 可以回到 0.5 附近（先不动，等第 1~3 段见效再单独验）。

### 第 5 段：显示层已完工

`seat = round(φ/90°)`，一格耗时 = 90°/ω，与 `state(6)` 同源。

## 六、为什么这不是"又一个补丁"

- 没有新增可调门限，反而**删掉 2 个绝对速度门 + 3 条重复通道**；
- 唯一新增的复用参数 `N=60` 有解析依据（σ_ω = σ_α/√Sxx 反解出来的），不是试出来的；
- 观测量的选择由 SNR 决定（0.08/帧 → 必须 ≥40 帧），不是"感觉这样更好"。

## 八、工作量与风险

- 改动集中在 `RotatingArmorTracker::associateAndUpdate` 的窗口段 + `TrackerConfig`
  若干字段，约 120~150 行，一个文件为主；`ekf_tracker` 是唯一硬门。
- **风险 1**：60 帧（0.36 s）窗口在 ω 快速变化时滞后。RM 自转的角加速度有限，
  可接受；必要时对 `σ_ω` 随残差放大做自适应（不加门限，只在 σ 里体现）。
- **风险 2**：换板清空缓冲会短期缺量测（每次约 60 帧 ≈ 0.36 s 无 rate 更新）。
  在此期间靠 `φ += ω·dt` 惯性推进，这正是低 Q 的用武之地；若实测抖动明显，
  再考虑"按板分缓冲"（每块板一条，命中哪块用哪条），不加门限。
- **风险 3**：`fold90` 展开在单帧噪声 13.8mm 下，若相邻帧角度差接近 45° 会折错。
  1.1 rad/s 下每帧 0.4°，安全；8 rad/s 下 2.9°，仍远小于 45°，安全余量足够。
