课程大作业：RoboMaster 自瞄视觉链路（相机取流 → 装甲板检测 → PnP 位姿解算 →

EKF 的设计依据与验证结果。细节记录见 `tests/README.md`；EKF 的设计推导见
`docs/EKF设计说明.md`。

## 2. 环境与构建

## 3. 各环节实现与数据

### 3.1 相机取流（15 分项）

`get_pic()` 一次初始化、取流、像素格式转换、异常处理；`release_camera()` 成对
释放；断线重连、错误日志分级、初始化重试。问题与修复见 `tests/README.md` §3。
`main.cpp` 里帧超时（500 ms）或空帧超过 3 次才退线程，其余情况补黑帧继续跑流程，
最终强制无目标输出。

### 3.2 相机标定

当前填入的是**车上相机**的内参（2026-10-22 用实车相机重标）：

```text
fx=1782.6  fy=1784.3  cx=749.4  cy=574.7   1440x1080
畸变 [k1,k2,p1,p2,k3] = [-0.03570, -0.15330, 0, 0, 1.1905]
```

（上一版 2 号机台架数据 `fx=1806.2 fy=1804.7 cx=738.8 cy=526.3`、
`k1=-0.0761 k2=+0.1522` 已作废。新的这组没有附带 RMS，`mean_reprojection_error_px`
沿用 0.07 px——`CameraParameters::valid()` 要求它 ≥0，不能留 -1。）

**外参当前是拆分状态**：旋转仍是占位单位阵，平移 `t=[0.06711, 0, 0.05150]` 是车
上实测值。原来的判定 `extrinsicIsPlaceholder()` 用"R≈I **且** |t|max<1e-9"，于是
"R 是占位、t 是真的"这种状态被判成"已标定"，`rotationCameraToGimbal()` 原样返回
单位阵，而 90° 光学系重排被跳过；同时回放侧又强推这层旋转并把 t 清零——实跑和
回放走的不是同一条路。现在拆成两个判据：

* `rotationIsPlaceholder()`：R 为空 / 尺寸不对 / ‖R−I‖<1e-6 → 用固定旋转
  `kOpticalToGimbal`（相机 右/下/前 → 云台 前/左/上），首帧打印一次警告；
* `hasTranslation()`：t 非空且 ‖t‖∞>1e-9 → `cameraToGimbalPoint()` 加减 t。

`config/camera.yaml` 里 t 是**真的**、R 是**占位**，两者互不影响；回放现在只把 t
清零（渲染用的世界原点在相机处），旋转交给 `armor_solve` 统一补。这样"实跑"和
"回放"对同一段视频给出同一套几何（`tests/test_ekf_pipeline.cpp` 有一条单测钉住：
R=I、t≠0 时必须走 90° 重排并加 t）。

### 3.3 装甲板检测（25 分项）

YOLO 关键点模型（sp_vision_25 的 yolov5，OpenVINO IR）直接回归四角点，同时给出
颜色/编号/大小：

* 检出率：实拍抽帧 红 64/64、蓝 141/141，**100%**；
* 速度：CPU 单帧 18~25 ms（640x640 输入）；默认输入已改为 **640x480**（见 §3.3.1），
  推理耗时再降 20%~25%；
* 输出直接是 PnP 需要的 TL,TR,BR,BL，无需额外分类器；
* 已知短板：个别倾斜角度四角点抖动，靠下游 EKF 平滑。

#### 3.3.1 推理输入尺寸优化（第三轮迭代）

相机是 4:3（1440x1080），正方形 640x640 输入把画面缩到 640x480 后余下 160 行
全是黑边：**该看的像素一个没少，多出来的 25% 卷积全是零**。因此把模型输入网格
裁成与画面同比例：

* 生成：`tools/make_small_ir.py` 支持 `WxH`，离线把 yolov5 的 Reshape 常量动态化
  并在目标尺寸上烘焙 meshgrid 常量（非正方形必须烘焙，动态子图会按形状缓存广播
  导致"形状合法但结果错"）；
* 精度：同一批实拍帧上检出数量/编号/大小板判定与 640x640 **完全一致**，PnP 相对
  差 ≤0.8%，同帧角点差 1~4 px；
* 速度：同进程 AB 交替推理（150 次/尺寸）最小 5.06 / 6.23 / 3.52 ms、
  中位 7.32 / 9.40 / 5.19 ms（640x480 / 640x640 / 512x384），即 640x480 省 20%；
* 512x384 再省 43%，但实拍远距（6~9 m）召回从 1/3/1/1/1 掉到 0/1/1/0/0，
  只能用于近距或吞吐测试；
* 兼容：`RMV_DET_SIZE=640` 可随时回到正方形输入，模型文件缺失自动回退。

复现基线：`./build/bench_detect tests/data/synth_small_1.png 120`（第四段为 AB 交替）。

### 3.4 PnP 位姿解算（15 分项）

按大小装甲板分别建物点（小 135×57 mm、大 230×57 mm），`solvePnP(IPPE)`；重投影
误差 > 6.0 px 拒绝（阈值按误差分布 P95≈4 / 坏批次 P50≈8 定）。平面目标的"孪生
解"用时域一致性消歧（误差差 > 3 px 以误差为准，否则取与上帧法向最近的解）。
实测重投影误差 1.6~1.8 px，距离帧间抖动 ~1 cm。

`armor_solve` 额外输出板面法向（云台系，`normal_gimbal`/`armor_yaw`）供 EKF
确定首帧相位——只有标量 yaw 会丢掉法向的俯仰分量。

## 4. EKF 跟踪与预测（20 分项）

### 4.1 模型选择

状态取 9 维：`[cx, vx, cy, vy, z, vz, yaw, yaw_rate, radius]`。它把任务书要求的
"车体中心平移、车体 yaw、角速度、装甲板高度、旋转半径"全覆盖了；观测用 3 维板心
位置（`[cx - R cosφ, cy - R sinφ, z]`，`φ = yaw + 2πk/N`）。这样同一套模型既能
描述"小陀螺"（`yaw_rate` 非零），也能描述静止/平移目标（`yaw_rate ≈ 0`），
不需要为两种工况切换模型。

工程上刻意保持"单一公式真源"：模型数学只在 `RotatingArmorModel.*` 里写一遍，
EKF 本体与粘合层都调它，新增功能不允许复制公式（这是上一版草稿最严重的问题：
`.cpp` 里重复实现了一份模型且从未编译）。

### 4.2 初始化：为什么必须两段式

3 维观测、9 维状态，单帧自由度足够"拟合得很好"，因此**不能用拟合残差判断参数
是否收敛**。合成真值实验（`ekf_model_convergence`、`ekf_init_contract`）：

* 单帧板残差只有 4~8 mm 时，车体中心误差仍可能是 0.3~0.43 m——观测被
  "相位在转"解释成"中心+半径偏了一点"；
* `omega=0` 冷启动在 8 个噪声种子上只有 5 个能锁进正确极小值，失败的种子都呈现
  "板对、车体全错"；给 `omega≈2` 的先验则 8/8；
* 反过来"静止目标 + omega 声明"也无法从数据学出来：对静止目标，"yaw 缓慢漂移 +
  中心同步平移"是模型的近零空间方向，板位几乎不变。

所以"转不转、多快"必须在锁定阶段声明出来，并且**静止声明是硬约束**
（`spin_pinned` 把角速度的整块过程噪声清零，包括 (6,7)/(7,6) 交叉项——只清 (7,7)
会让该 2×2 块行列式为负，Q 不再半正定）。声明错了要能被观测反驳：
`declarationContradicted` 用板面法向的斜率与 EKF 的 `yaw_rate` 比对，连续 6 帧
偏差 > 1 rad/s 就重锁。

### 4.3 关联、换板与门限

每帧先预测到本帧时刻，再在"观测 × 槽位"上取距离最近且满足 `≤0.6 m` 与
NIS `≤11.34`（3 维 99.5%）的一对做更新，最多 2 块板。瞄准板选择带 0.06 rad
迟滞，避免两块板等距时来回跳。离群观测由距离门限 + NIS 双重拒绝。

### 4.4 短时遮挡与超时

无观测时 `ekf_predict` 仍被调用（任务书 §4 的要求），只跳过更新、照常预测；
连续丢帧 ≥2 帧降为 `Unstable`（`crc=2`，禁开火），超过 0.6 s 清空为
`NoTarget`（`crc=0`）。冻结观测做 0.3 s 纯外推，板位置误差 0.0198 m。

### 4.5 输出与安全

预测时域 = 电控下发的 `prediction_bias_s` + 本帧实测处理延迟
（`steady_clock::now() - timestamp_seconds`，限幅 0.3 s）：前者是弹道/回路补偿，
后者是"取到帧到算出结果"已经花掉的时间，两者是不同环节。实测：0.5 m/s 平移
目标加 0.1 s 延迟，预测距离前推 0.050 m（= v·t）。

预测时域里再加一项**弹丸飞行时间** `range / v0`（`v0=30 m/s`，`max_flight_s=0.5`，
`flight_compensation_enabled` 可关）：30 m/s、2 m 距离是 67 ms，自转 3 rad/s 的板
在这段时间里跑 5 cm，比小板半宽的一半还多。距离用预测后的车心估计、迭代两次收敛。
这与 `sp_vision_25` 的 `aimer.cpp:86`（`predict_time = future + fly_time` 迭代）一致；
`prediction_bias_s` 是电控在此之上的额外偏置，两者叠加而不是互相替代。

`PredictionResult` 填中心位置/速度/yaw/角速度/半径/距离/目标绝对角度/角速度/
开火许可。开火条件：`Stable`、本帧有更新、距上次更新 ≤0.2 s、距离在 0.4~12 m，
并且**把角度误差换算成板面内的脱靶量**后仍在板内：`distance·tan(yaw_err) ≤
0.6·half_w` 且 `distance·tan(pitch_err) ≤ 0.6·half_h`（`half_w` 大 0.115 / 小
0.0675，`half_h=0.0285`）。旧判据是"角度误差 ≤0.05 rad"，在 1.5 m 就是 7.5 cm，
比小板半宽还大、竖直方向是半高的 2.6 倍——角度"对上了"照样打飞。任一字段非有限
则整帧无目标，框架
`applyPrediction` 再兜底一次（NaN → `setSafeOutput`）。

`fire_allowance=1` 的 184 帧全部落在 `crc=1`；早期未锁定时输出完整的

### 4.7 讨论与限制

1. **车体 yaw 只能确定到 2π/N**：N 块装甲板几何上完全相同，把 yaw 平移 2π/N 后
   板位集合不变，属于模型固有对称性而非估计误差。不影响瞄准与角速度，但报告与
   答辩需说明（测试按模 2π/N 断言）。
2. **单半径、等高**：前哨站那种交替高度/半径的目标需要按槽位扩展状态；
   `PredictionResult::radius_2_m` 已预留。
3. **首帧半径依赖先验**：视场内只有一块板且目标静止时，半径取先验 0.25 m；
   与实际偏差大时中心估计会整体偏移。
4. **外参未标定**：外参仍是占位单位阵时，`armor_solve` 会按"相机光学系 →
   云台系"的固定旋转重排坐标轴（`rotationCameraToGimbal()`，首帧打印一次警告），
   因此跟踪的**相对几何**（中心、半径、角速度、换板）是自洽的；但相机相对云台
   回转中心的平移 `t` 与安装倾斜仍未知，绝对瞄准角存在系统偏差。这是现场验收前
   必须补的一项：按 `docs/云台外参.md` 标定后用真实 `R/t` 替换
   `config/camera.yaml`，再复测上表中的距离类指标。
5. **关联是最近邻**：同色同编号多车场景无法区分，依赖 `target_id`；全局最优
   分配在这个可见板数（≤2）下没有收益。

### 4.8 真数据回放（`tests/test_camera_playback`）

把 `tmp/v1.avi`、`tmp/v4.avi` 送进完整链路（检测 → PnP → EKF），云台角按 0 处理、
外参占位按固定旋转摆正。

| 场景 | 结果 |
| --- | --- |
| `v4`（相机固定，两台道具：1 号大板 2.05 m 静止、3 号小板 1.2~1.8 m 平移） | 帧 30 锁定 1 号板，`Stable` 1374/1415（97%），重锁 0、切换 0；预测命中中位 **6.7 mm**、p90 15.1 mm、≤5 cm 99.9%，瞄准误差中位 3.7 mm |
| `v4 --only-id 3`（只留 3 号小板） | 帧 152 锁定，`Stable` 734/1415，重锁 1；预测命中中位 9.7 cm——这台是自制道具，装甲基半径实测 0.31 m，与按板型选的先验 0.20 m 差太多，单板可见时"半径 vs 车心"不可分辨 |
| `v1`（手持晃动，两车先后入画） | 帧 22 锁定，`Stable` 481/608（79%），重锁 1、切换 2；预测命中中位 8.1 cm、≤5 cm 34%，瞄准误差中位 4.9 cm |

识别本身不是瓶颈：两段视频的 PnP 重投影残差中位只有 0.26 px（v4）/ 0.30 px（v1），
p90 0.72/0.55 px；误差全部来自"相机系 → 世界系"这一步（云台报告姿态）。所以 v1 的
残差不是检测或 PnP 的问题，而是没有 IMU 可用时世界系本身在晃。

"v4 在 800 多帧圆心偏了"的三个真原因（逐个用 `--trace` + 俯视图定位）：

1. **目标在两台车之间来回切换**：`prefer_centered_target` 每次另一台车更靠准星
   0.10 rad 就换目标，换一次要重新攒 30 帧样本，整段只有 299 次更新。
   把切换迟滞 `target_switch_margin_rad` 提到 0.30 后，切换 0 次、更新 1384 次，
   预测误差中位从 5.9 cm 掉到 0.68 cm。这是最大的一笔收益。
2. **把噪声当转速**：法向在 ±45° 折叠边界附近来回翻，逐帧微分给出 16 rad/s 的假
   角速度，模型四块板整圈自转。改成 0.35 s 窗口的 Theil-Sen + 换板续接 + 双路
   证据 + 无证据衰减（`tests/README.md` §"转速自判"）。
3. **锁定半径被噪声带偏**：单板时半径与车心不可分辨，冻结之后整段错。现在圆拟合
   给出的半径离板型先验超过 30% 就退回先验，双板直解优先。

另外两处小修：单板重锚只在"上一帧一次更新都没进去且连续 miss≥3"时生效（否则
离群观测会绕过 NIS 门）；锁定弦长兜底不再声称零拟合误差。

限制：高速自转目标在"每帧只露一块板"时 `Stable` 受可见率限制，属观测不足；
若验收要求更高，应把车身相位（模 `π/2`）升为主观测。详见 `docs/EKF设计说明.md` §12。

### 4.9 俯视图绿圈：单一观测圆估计器

绿圈（俯视图里"实测车心 + 观测圆"）以前不是一个估计量：同一帧可能在
**≥2 板两圆交点 / 单板沿法向退 R / EKF 车心方向兜底 / 1.2 s 窗口自由拟合 R**
四个解之间切换，再套 5 帧中位。检测阈值 0.7 让板数在 1↔2 之间翻，四个解来回跳，
画面上表现为"绿圈抖"。实测单帧解与滤波后解差 `raw` 中位 **61.7 mm**——旧显示
就是拿这个量级在画。

现在换成 `src/TopDownView.cpp` 里的 `ObservedBodyEstimator`：常速模型
`[cx,vx,cy,vy]` 的卡尔曼，每块观测到的板给两路正交标量观测（法向 σ=12 mm 取
PnP 板心噪声；切向 σ=√(12²+(R·0.10)²)≈25 mm，因为板心沿切向的位置靠法向角度
决定，`R·δθ` 就是误差），Huber 在 3σ 外放大 σ 而不是丢观测，半径走每帧 0.03 的
EMA（τ≈0.2 s，解决 R 从 0.16 爬到 0.27 时车心沿法向平移 10 cm），`|v|` 限幅 3 m/s。
覆盖度取最近 1 s 内板法向 yaw 的圆周跨度，`confidence = 0.5·(1−residual/0.03) +
0.5·(coverage/120°)`；低信度只画细线浅色并标 `LOW`，不再假装可信。

v4 实拍（`DET_JITTER=1 ... --topdown`，631 帧有解）：

| 指标 | 数值 |
| --- | --- |
| 帧间跳变 `jump` | p50 **3.1** / p90 **6.8** / p99 12.6 mm |
| 跳变 >30 mm 的帧 | 2 帧（最大 207 mm 是目标切换，不是抖动） |
| 对 5 帧中位偏离 `stab` | p50 4.6 / p90 13.1 mm（这部分主要是真实运动） |
| 单帧解与滤波解之差 `raw`（旧口径） | p50 **61.7** mm |

即：把"换估计量"的 7 cm 量级压到 3~7 mm，30 fps 显示口径下肉眼不再跳。
`[jit]` 行同时输出 `cov/res/conf`，可以在不确定时看出来（而不是靠感觉）。

### 4.10 命中度量：到底打没打中

"视频里蓝绿贴合"是自证口径：瞄准点就是从那一帧观测推出来的，同帧对账当然好看
（95.5% ≤5 cm）。真正的验收要独立：瞄准点 vs **子弹到达那一刻**的板。

判定（`tests/test_camera_playback.cpp` 的 `reportHitMetrics`）：

* 参考时刻 `= 开火时刻 + 弹丸飞行时间 (range/30)`，在 ±10 ms 内取**离瞄准点最近
  的同 id 板**（两台车只露两块板时，两板均值会把"打中其中一块"判成没中）；
* 三轴分解：法向（深度，**不计命中**，只诊断）、竖直（±28.5 mm）、
  切向（大板 ±115 / 小板 ±67.5 mm）；
* 命中 = 切向、竖直都在板内 **且** 板面朝相机。

v4 基线（`--red --ekf --headless`）：

| 指标 | 值 |
| --- | --- |
| 到期对准 / 可评估 | 1384 / 985（71.2%，其余 399 次该时刻无同 id 观测） |
| 切向 |e_t| | p50 2.17 cm / p90 17.04 cm |
| 竖直 |e_z| | p50 1.51 cm / p90 8.30 cm |
| 命中率 | **430/985 = 43.7%** |
| 按 \|ω\|：<1 / 1–5 / >5 | 53.5%（693） / 26.1%（211） / 4.9%（81） |
| 同口径分档竖直误差 | 0.95 / 4.57 / 7.24 cm（p50） |

**时间偏移扫描**（参照时刻再挪 offset）：峰值在 **−40 ms、70%**，0 ms 是 50%，
+40 ms 又出现一个次峰。这说明：

1. 全链路（曝光 → 处理 → 下发 → 弹道）的有效提前量比"开火 + 飞行"少约 40 ms，
   即便把 offset 调到最优也只有 70%——**剩余误差不是单纯的时间偏移**；
2. `|ω|<1` 档只有 53.5%：静止/慢转目标的瞄准点有 1/4 落在板外 >6.75 cm。这一档
   里 EKF 的 `z` 在整段里摆了 14 cm（`z` 0.227 → 0.086 → 0.157），竖直 p90 7.93 cm
   ——竖直是仅次于相位的第二大漏洞，且和"板面法向随转速摆动把 z 带偏"有关。

合成场景 G（`test_rotating_armor_tracker`）同步改成按"延迟 + 飞行时间"取真值。
改之前它把 2~8 rad/s 的提前量判成脱靶（因为它只按 50 ms 延迟算真值）；
改之后 2/4/6/8 rad/s 的 3 cm 命中率是 98/100/100/96%，"瞄在朝相机那面"的占比
100/99/99/95%。顺带修掉一个真 bug：保持上次瞄准槽位时没有复查"它在开火时刻还
朝不朝相机"，8 rad/s 下 24% 的帧瞄在已经转到背面的板上。

## 5. 结论

* 全链路（取流 → 检测 → PnP → EKF → 通信帧）在离线数据与仿真上闭环，11 项
  ctest 中 10 项全绿（`camera_grab` 需接相机）；实机验收只差外参标定后联机复测。
* 命中要单独度量：同帧对账 95.5% 是自证，按"弹丸到达时刻"算 v4 只有 43.7%。
  差距里最大的一块是**提前量**（偏移扫描峰值 −40 ms、70%），其次是**竖直**（`z`
  估计摆动 14 cm）。这两项都不是"算法没写"，而是需要真车标定与 P/Q 调参。
* EKF 的核心结论有三条：单帧拟合残差不能判收敛；"转/不转"不能用逐帧微分判，
  要用窗口证据 + 反证据（并接受"数据说不清就不改"）；判错了必须用**纯外推误差**
  而不是滤波残差来暴露——有观测时 yaw 会把相位吸收掉，NIS 照样自洽。

   10~15 组姿态（yaw ±60°、pitch ±30°，纯 yaw / 纯 pitch / 混合都要有），

   当前 R 是占位单位阵：相对几何自洽，但绝对瞄准角有系统偏差。
2. **P/Q 调参（同一趟实车）**：重点是 `z`（静止段摆了 14 cm）与半径/角速度的

   现在是 0，而扫描显示有效提前量差约 40 ms，这个数要在实车上量出来。
4. 全链路实机验收（含旋转车体、装甲板切换、遮挡恢复三个必验场景）。
