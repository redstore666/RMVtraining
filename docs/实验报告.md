# 自瞄视觉链路实验报告

RoboMaster 视觉组个人大作业。本报告按评分表七项组织：每一项写明实现方式、设计依据、
实测数据和剩余问题。EKF 的完整推导和二十余次针对性实验的过程记录在
`EKF设计说明.md`，本文只给结论。

---

## 1. 系统组成

一条处理链路，每帧依次经过下列环节，任一步失败都降级为"无目标"而不是崩溃：

```
串口读线程 ──── 最新云台数据（互斥锁保护）
                      │
操作线程每帧:          ▼
  get_pic          海康相机取流，MVS SDK，BGR 输出
  armor_detect     YOLO 关键点模型（OpenVINO），四角点 + 编号 + 大小 + 置信度
  armor_solve      solvePnP(IPPE) → 云台系三维板心 + 板面法向
  ekf_predict      11 维 EKF：车体中心/速度/高度/yaw/角速度/半径
  输出合法性检查   NaN、过期、未稳定一律禁开火
  填写通信结构体   64 字节，crc 字段写 EKF 状态
  串口写           ──── 电控
  WEB_LOG          Web Debug 曲线
```

代码分工：`student/` 是本人实现（四个接口 + 检测器 + 模型 + EKF + 跟踪器 + 几何换算），
`main.cpp`、`serialPort/`、`web_debug/`、`armor/` 为教师提供的框架与参考代码，
框架的线程结构和通信结构体未改动。

## 3. 串口与双线程

对应评分项"串口与双线程"（10 分）。

### 3.1 通信帧

64 字节结构体的字段、类型、顺序和总长均未改动，字段含义见 `通信结构体.md`。
框架里几个容易误解的点：

- `crc` 不是校验和，是 EKF 状态：0 = 无目标，1 = 预测稳定，2 = 有目标但未稳定。
  没有实现任何 CRC 算法。
- `target_id` 是装甲板上印的数字（1~8），不是车辆编号。同一辆车的四块板印的是
  同一个数字，因此不能用它区分车辆。
- `center_x/center_y` 单位是毫米，EKF 内部用米，出帧前统一乘 1000。

### 3.2 线程分工

读线程只做一件事：从串口读满一帧、检查帧头帧尾、写入 `latest_gimbal_`。
操作线程复制一份云台数据后完全脱离共享区，之后取流、检测、解算、预测都不再碰
共享变量。

共享数据用一个 `std::mutex` 保护，读写都取锁，读线程不做任何计算、操作线程不在
持锁期间做耗时操作。这样最坏情况下读线程等一次拷贝的时间（微秒级），不会因为
算法卡顿丢帧。

### 3.3 退出

`SIGINT` 置位一个 `std::atomic<bool>`，两个线程各自在循环条件里检查。退出顺序是
先停读线程（停止串口读）、再停操作线程（退出前把相机流停掉并释放句柄）、最后
`STOP_WEB_SERVER()`。

相机释放走 `release_camera()`，和 `get_pic()` 里的初始化成对出现。MVS SDK 要求
`MV_CC_StopGrabbing` 和 `MV_CC_CloseDevice` 必须配对，漏一步会导致下次启动时
设备被占用。

### 3.4 空帧与超时

`pic.empty()` 时不立刻回安全包，而是按任务书第 4 节的要求让黑帧继续走完检测、
PnP、EKF 三轮，让 EKF 有机会做纯预测；连续空帧超过 3 次才退出操作线程。最终输出
仍然强制为无目标。帧超时设为 500 ms。

## 4. 相机取流与标定

对应评分项"相机取流与标定"（15 分）。

### 4.1 get_pic

一次初始化、重复取流的结构：

| 阶段 | 处理 |
| --- | --- |
| 设备枚举 | `MV_CC_EnumDevices` 按 GigE 和 USB 两类枚举，取第一台；无设备时打印可用设备数并返回 false |
| 打开与配置 | 连续采集模式，关闭自动曝光和自动增益，像素格式设 `PixelType_Gvsp_BGR8_Packed` 由 SDK 直接转 BGR，省掉一次 `cvtColor` |
| 取流 | `MV_CC_StartGrabbing` 后循环 `MV_CC_GetImageBuffer`，超时 500 ms；超时返回 false 由上层计数 |
| 异常 | 取流中断（`MV_E_NODATA` 等）先 `StopGrabbing` 再重新 `StartGrabbing`，最多重试 3 次；仍失败则释放句柄返回 false |
| 释放 | `MV_CC_FreeImageBuffer` 每帧必调；`release_camera()` 里按 StopGrabbing → CloseDevice → DestroyHandle 顺序逆序释放 |

超时和断流的实测表现：拔掉网线后程序在 3 次重试内报错，操作线程继续跑（喂黑帧），
Web Debug 曲线上的 `grab_ms` 变成 0，恢复连接后自动继续取流，不需要重启进程。

### 4.2 内参标定

棋盘格 9×6，方格 25 mm，用 `tools/calib_capture` 采集 21 张不同姿态的图（存
`calib_data/`），`tools/calibrate_intrinsics` 调 `cv::calibrateCamera` 解算。
采集时刻意覆盖了四个角和中心、以及 ±30° 的倾斜，避免全部正对导致畸变参数不可观。

当前填入 `config/camera.yaml` 的是车上相机（2026-10-22 重标）：

```
fx = 1782.6    fy = 1784.3    cx = 749.4    cy = 574.7    图像 1440×1080
畸变 [k1, k2, p1, p2, k3] = [-0.03570, -0.15330, 0, 0, 1.1905]
```

重投影误差 0.07 px。这组参数在静止实拍上给出的 PnP 重投影残差中位 0.57 px、
100% 的帧在 1 px 以内，说明内参和板尺寸的配合是自洽的。

### 4.3 外参：当前是拆分状态

这是本次提交最需要说明的一处。外参的旋转和平移目前来自不同来源：

- 平移 `t = [0.06711, 0, 0.05150] m` 是车上量的实值（相机光心相对云台回转中心）；
- 旋转仍是占位单位阵，实际使用的是固定的坐标轴重排
  `kOpticalToGimbal`（相机 右/下/前 → 云台 前/左/上）。

这个状态曾经导致一个隐蔽 bug：原来的判据是"R≈I **且** |t| 很小"才算未标定，
于是"R 是占位、t 是真值"被判成已标定，90° 重排被跳过；而回放侧又强制施加这层
旋转并把 t 清零，两边走的不是同一条路。现在拆成两个独立判据：

- `rotationIsPlaceholder()`：R 为空、尺寸不对、或 ‖R−I‖ < 1e-6 时用固定旋转，
  并在首帧打印一次警告；
- `hasTranslation()`：t 非空且 ‖t‖∞ > 1e-9 时才做平移。

`tests/test_ekf_pipeline.cpp` 有一条单测钉住这个契约：R=I、t≠0 时必须走 90° 重排
并且加 t。

标定方法写在 `云台外参.md`：棋盘固定，云台取 10~15 组姿态（yaw ±60°、pitch ±30°，
纯 yaw、纯 pitch、混合都要有），`solvePnP` 得 `T_board←cam`，再用
`cv::calibrateHandEye` 解 `R_gimbal←camera`。验收看板心在云台系的离散度和重投影。
本次没做这一步，原因是实车只有两次上电机会，都用在链路联调上了。

**影响**：跟踪的相对几何（车体中心、半径、角速度、换板）自洽，第 7 节的实车数据
就是在这个状态下测的；绝对瞄准角存在安装倾斜带来的系统偏差，上车前需要补标定。

### 4.4 配置校验

`CameraParameters::valid()` 检查四件事：矩阵非空、内参是 3×3、畸变是 5×1、
所有值有限。任何一项不满足就打印具体缺哪一项并退出，不用默认值硬跑。
`calibrated` 标志为 0 时打印警告继续跑（回放需要），为 1 时才认为可以用于实弹。

## 5. 装甲板识别

对应评分项"装甲板识别"（25 分）。

### 5.1 路线选择

最终选神经网络路线：YOLO 关键点模型直接回归装甲板四角点，同时输出颜色、编号、
大小板类型和置信度。模型来自 `sp_vision_25` 的 yolov5，转成 OpenVINO IR 后在
CPU 上推理。

传统视觉路线（HSV 掩码 → 灯条提取 → 灯条配对 → 角点生成 → 数字分类）也完整实现
过并跑过实拍，最后放弃。放弃的理由不是精度，而是维护成本：环境光变化时要重调
HSV 区间，反光、遮挡、对面板的串扰每一样都要单独加规则，实拍里出现的"共享灯条
假板"、"掩码被上帧残留污染"、"孪生板翻号"三个问题，每一个都要加一条特判才能压住。
换成关键点模型后这三类错误直接消失。调试过程记录在 `tests/README.md` 第 5.2 节和
`tests/evidence/` 的取证图里。

### 5.2 输出约定

无论哪条路线，下游拿到的是统一结构：从左上角开始顺时针的四个像素角点、
`ArmorSize`（大/小）、`target_id`、置信度。`armor_detect` 不做 PnP，也不维护
跨帧状态，这一点按任务书第 5 节的分工要求保持。

检测不假定每帧都有目标：返回空 vector 是正常路径，不是异常。

### 5.3 检出率与速度

实拍抽帧（红方 64 帧、蓝方 141 帧，含远处小目标和斜视）：

| 指标 | 数值 |
| --- | --- |
| 红方检出 | 64/64，100% |
| 蓝方检出 | 141/141，100% |
| 编号错误 | 0 |
| 大小板误判 | 0 |
| CPU 单帧耗时（640×640 输入） | 18~25 ms |
| CPU 单帧耗时（640×480 输入） | 约省 20% |

### 5.4 推理输入尺寸

相机是 4:3（1440×1080），正方形 640×640 输入把画面缩到 640×480 后，余下 160 行
全是补的黑边。这些行的卷积结果恒为零，等于白算 25%。

把模型输入改成与画面同比例后（`tools/make_small_ir.py` 支持 `WxH`，非正方形必须
把 meshgrid 常量烘焙进去，用动态子图会因形状缓存导致"形状对但结果错"）：

| 输入尺寸 | 最小耗时 | 中位耗时 | 相对 640×640 |
| --- | ---: | ---: | --- |
| 640×480 | 5.06 ms | 7.32 ms | 省 20% |
| 640×640 | 6.23 ms | 9.40 ms | 基准 |
| 512×384 | 3.52 ms | 5.19 ms | 省 43% |

同进程 AB 交替各 150 次测得。精度上，640×480 与 640×640 在同一批实拍帧上的检出
数量、编号、大小板判定完全一致，PnP 相对差 ≤0.8%，同帧角点差 1~4 px。
512×384 再快 43%，但远距（6~9 m）召回从 1/3/1/1/1 掉到 0/1/1/0/0，只能用于近距
或吞吐测试，默认不启用。

`RMV_DET_SIZE` 环境变量可在运行时切换，模型文件缺失时自动回退到 640×640。

### 5.5 目标丢失

单帧漏检不会让 EKF 状态跳变：`armor_detect` 返回空，`ekf_predict` 收到空观测后
只做预测不做更新。连续漏检的降级路径在 7.4 节。

四段素材的跟踪覆盖率（有目标在跟的帧占比）：bluemove 99.4%、sinspeed 98.6%、
redrotate 97.0%、nearmove 88.5%。漏检主要集中在目标转到背向相机的那一段，
这是物理遮挡，不是检测器问题——nearmove 是近距大目标，转到背面时整块板消失，
掉得最多。

## 6. 位姿解算

对应评分项"位姿解算"（15 分）。

### 6.1 三维点与单位

按 `装甲板尺寸.txt` 分别建立：小板 135×57 mm，大板 230×57 mm。物点在建表时
显式除以 1000 转成米，之后全部计算统一用米，出通信帧时才乘回毫米。这一处如果
留着毫米，EKF 的过程噪声量级会差三个数量级，表现是滤波器完全跟不上。

### 6.2 PnP

`solvePnP` 用 `SOLVEPNP_IPPE`，四种角点顺序按任务书约定（左上起顺时针）。
IPPE 专门处理平面目标，比 `ITERATIVE` 稳定，也不会像 `SQPNP` 那样在接近正对时
退化。

重投影误差超过 6.0 px 的观测直接丢弃。阈值来自误差分布：正常批次的 P95 约 4 px，
坏批次（角点错位）的中位就有 8 px，取 6.0 能分开两者。

### 6.3 坐标系与坐标轴

三个坐标系，方向约定如下（答辩需要能画出来）：

| 坐标系 | x | y | z |
| --- | --- | --- | --- |
| 相机光学系 | 右 | 下 | 前（光轴） |
| 云台系 | 前 | 左 | 上 |
| 世界系 | 前 | 左 | 上（与云台系同向，原点在云台回转中心，yaw 归零时重合） |

相机系到云台系是固定旋转加平移：`p_gimbal = R · p_camera + t`。R 为占位时用
`kOpticalToGimbal`，即上面这张表的轴重排。

`armor_solve` 除板心外还输出板面法向（`normal_gimbal`、`armor_yaw`）。只给标量
yaw 会丢掉法向的俯仰分量，EKF 首帧就无法确定车体相位，只能靠猜。

### 6.4 平面目标的孪生解

平面 PnP 有两个解（法向关于视线对称），IPPE 会给出两个候选。消歧策略：
两个解的重投影误差差超过 3 px 时以误差小的为准；差异不明显时取法向与上一帧最接近
的那个。没有上一帧（首帧）时取朝向相机的那一个。

### 6.5 实测误差

| 场景 | 重投影误差中位 | 距离帧间抖动 |
| --- | ---: | ---: |
| 静止目标（58 s，无运动） | 0.57 px | 1.3 cm |
| 平移目标 | 2.63 px | ~2 cm |
| 旋转目标（ω≈4.7） | 1.72 px | ~2 cm |

静止时 100% 的帧重投影误差在 1 px 以内。平移时恶化到 2.63 px 是运动模糊导致的
角点定位精度下降，不是解算本身的问题。

## 7. EKF 跟踪与预测

对应评分项"EKF 跟踪与预测"（20 分）。这是本作业的主要工作量，推导见
`EKF设计说明.md`，这里给结论和数据。

### 7.1 状态与观测

11 维状态：

```
x = [cx, vx, cy, vy, z, vz, yaw, yaw_rate, radius, radius_diff, height_diff]
```

前九维覆盖任务书要求的"车体中心平移、车体 yaw、角速度、装甲板高度、旋转半径"，
后两维 `radius_diff`、`height_diff` 是四板车的**非对称刚体参数**：前后一对板比左右
一对离车心更远、也常高一点。偶数槽位用 `radius`，奇数槽位用 `radius + radius_diff`，
高度同理。它们只在同帧双板可见时才有信息（单板帧对应雅可比列为零），所以默认开启、
由滤波器自己决定信不信——不开这两维时，那 1~3 cm 的装配偏差只能被 yaw/中心吸收，
表现为双板帧的第一帧 yaw 单帧跳 0.17~0.19 rad。

观测是 3 维板心位置。板心由车体状态决定：

```
p_plate(k) = [cx - R·cos(φ + 2πk/N), cy - R·sin(φ + 2πk/N), z]
```

φ 是车体 yaw，N 是板数（4）。这个式子只写一遍，EKF 本体和跟踪器都调它，不允许
复制第二份实现——上一版草稿在 `.cpp` 里重复实现了一份且从未编译，是那版最严重的
问题。

模型对"静止/平移"和"小陀螺"是同一条公式，不需要按工况切换，差别只体现在
`yaw_rate` 是否为 0。

### 7.2 初始化：为什么必须两段式

3 维观测估 11 维状态，单帧自由度足够拟合得很好，所以**不能用拟合残差判断收敛**。
合成真值实验说明了这一点：

- 单帧板残差只有 4~8 mm 时，车体中心误差仍可能是 0.3~0.43 m。观测被"相位在转"
  解释成"中心偏了一点加半径偏了一点"，两种解释在单帧上等价；
- `yaw_rate=0` 冷启动在 8 个噪声种子上只有 5 个能锁进正确极小值，失败的都呈现
  "板对、车体全错"；
- 反过来，静止目标也无法从数据里学出"它在转"：对静止目标，"yaw 缓慢漂移 +
  中心同步平移"是模型的近零空间方向，板位几乎不变。

所以"转不转、多快"必须在锁定阶段声明，静止声明是硬约束（`spin_pinned` 把角速度
对应的整块过程噪声清零，包括 (6,7)/(7,6) 交叉项；只清 (7,7) 会让 2×2 块的行列式
为负，Q 不再半正定）。

声明错了要能被观测反驳：`declarationContradicted` 比较板面法向的斜率与 EKF 的
`yaw_rate`，连续 6 帧偏差超过 1 rad/s 就重新锁定。

### 7.3 关联、换板与门限

每帧先预测到本帧时刻，再在"观测 × 槽位"上求和距离最小且同时满足位置门限
≤0.60 m、NIS ≤14.86 的一对做更新，最多用 2 块板。

NIS 门限取 14.86 是 χ²(4) 的 99.5% 分位。跟踪层在同时拿到板面法向时会把它作为
第 4 维，没有法向时该维方差置 1e9、贡献为 0，等价于 χ²(3)。取 14.86 是"最多 4 维"
的保守上限，不会因为门开大而放进离群点。

关联时按 `target_id` 过滤，不同编号的观测不参与同一辆车的关联。这一条是踩过坑
补上的：早期版本没过滤，两台同色车靠近时会把 B 车的板更新进 A 车的 EKF。

瞄准槽位直接跟随本帧被接受更新的那块板，不做迟滞。四块板物理等价，把瞄准点
绑在刚看到的那块上误差最小；如果沿用上帧的槽位，发布的瞄准点会指向模型外推
90° 后的另一块板，误差随相位漂移放大。离群观测由位置门限和 NIS 双重拒绝。

瞄准点只允许落在"最近 0.30 s 内真的被看见过"的板上。四块板里总有一两块朝向车体
背面，几何上存在但检测不到，只按角度挑会挑到它们身上——实拍 v4 上有 1384 帧
瞄准点全落在 slot 3，而实际看见的是 slot 0，误差 0.35 m。

`prefer_centered_target` 默认关闭。它会在"另一台车更靠近准星"时切换目标，实测在
两台车场景里造成 299 次切换（每切一次要重新攒 30 帧），预测误差中位从 5.9 cm
涨到 0.68 cm 的反面。关掉后切换 0 次、更新 1384 次。

### 7.4 遮挡、超时与重锁

无观测时 `ekf_predict` 照常被调用，只跳过更新、继续预测（任务书第 4 节要求）。

| 情况 | 状态 | crc | 开火 |
| --- | --- | --- | --- |
| 正常 | Stable | 1 | 允许（还要过 7.5 的几何检查） |
| 超过 0.1 s 未更新 | Unstable | 2 | 禁止 |
| 丢失 >0.6 s | NoTarget | 0 | 禁止 |

Unstable 的判据是"距上次被接受的更新超过 `max(stale_min_s, stale_min_frames × 帧间隔)`"，
默认 0.05 s 和 5 帧取大，上限由 `stale_after_s = 0.10 s` 封顶。这样在 165 fps 下
是 5 帧、在 30 fps 下是 0.1 s，两种帧率都不会误判。

0.6 s 这个数来自外推精度：冻结观测做纯外推时，板位置误差在 0.3 s 是 0.0198 m，
到 0.6 s 涨到 0.09 m 量级，再往后误差就超过板宽了。

遮挡 0.25 s 的实测：全程保持预测、状态有限、禁开火、记录丢帧数，恢复后重新进
Stable。丢失 1.0 s：输出 NoTarget、跟踪器清空、`target_id` 归零。

### 7.5 输出与开火许可

预测时域 = 电控下发的 `prediction_bias_s` + 本帧实测处理延迟 + 弹丸飞行时间。

三项是不同环节，不能互相替代：

- `prediction_bias_s` 是电控的回路补偿，按任务书要求从 `GimbalState` 取，单位 s；
- 实测延迟 = `steady_clock::now() - timestamp_seconds`，"取到帧到算出结果"已经
  花掉的时间，限幅 0.3 s；
- 飞行时间 = `range / v0`，`v0 = 30 m/s`，上限 0.5 s。30 m/s、2 m 距离是 67 ms，
  自转 3 rad/s 的板在这段时间里跑 5 cm，比小板半宽的一半还多。

飞行时间用预测后的车心距离算，迭代两次收敛。这一段与 `sp_vision_25` 的
`aimer.cpp:86` 做法一致（`predict_time = future + fly_time` 迭代）。

**开火判据**是本次改动较大的一处。旧判据是"角度误差 ≤0.05 rad"，在 1.5 m 处就是
7.5 cm，比小板半宽 6.75 cm 还大，竖直方向是板半高 2.85 cm 的 2.6 倍——角度"对上了"
照样打飞。现在把角度误差换算成板面内的脱靶量：

```
distance · tan(yaw_err)   ≤ 0.6 · half_w
distance · tan(pitch_err) ≤ 0.6 · half_h
```

`half_w` 大板 0.115 / 小板 0.0675，`half_h` 0.0285。取 0.6 是留 40% 余量给弹道
散布和延迟抖动。

完整开火条件：状态 Stable、本帧有更新、距上次更新 ≤0.2 s、距离在 0.4~12 m、
上述几何检查通过。任一字段非有限则整帧无目标；`applyPrediction` 在框架侧再兜
一次底（NaN → `setSafeOutput`）。

### 7.9 实车回放：四场景命中率

这是本次验收的主要数据。四段实拍视频送进完整链路（检测 → PnP → EKF），云台角按
0 处理、外参按固定旋转摆正，逐帧比对"瞄准点"与"弹丸到达时刻的板"。

命中判定：参考时刻 = 开火时刻 + 弹丸飞行时间（range/30），在该时刻 ±10 ms 内取
离瞄准点最近的同 id 板，分解成法向（深度，不计命中）、竖直（±28.5 mm）、切向
（大板 ±115 / 小板 ±67.5 mm）三轴，切向和竖直都在板内且板面朝相机才算命中。

| 场景 | 转速 ω | Stable 帧 | 可评估 | 命中率 | 切向 p50 / p90 | 竖直 p50 / p90 |
| --- | ---: | ---: | ---: | ---: | --- | --- |
| bluemove（蓝，平移） | 0.07 | 4774 | 4860/4874 | **99.8%** | 0.15 / 0.88 cm | 0.09 / 0.46 cm |
| nearmove（蓝，近距平移） | 0 | 2232 | 2627/3158 | **85.5%** | 1.57 / 11.53 cm | 0.41 / 2.16 cm |
| redrotate（红，旋转） | 4.69 | 875 | 960/974 | **67.0%** | 3.72 / 26.62 cm | 0.93 / 3.88 cm |
| sinspeed（蓝，高速旋转） | 4.90 | 1968 | 2046/2070 | **32.2%** | 9.94 / 29.28 cm | 1.94 / 9.99 cm |

读法：

静止和平移目标（ω≈0）的命中率 99.8%，切向中位 0.15 cm，已经接近 PnP 自身的
抖动水平，没有提升空间。

失效几乎全部来自切向误差，且随转速升高而成比例放大。竖直误差在 ω<5 时 p50 都在
2 cm 以内（板半高 2.85 cm），只有 sinspeed 的 p90 到 9.99 cm，说明高速段车体
高度估计也被带偏。

redrotate 与 sinspeed 转速相近（4.69 vs 4.90），命中率差 2 倍，差别在可见板数：
sinspeed 素材里同帧出现两块板的帧只占 0.6%，等于全程单板观测。单块板只能给出
一个板心，车体中心和半径的分解靠模型先验（半径锁 0.28），相位信息不足直接放大成
切向误差。redrotate 有相当比例的双板帧，相位可观测，切向中位就掉到 3.72 cm。

这条结论解释了为什么 sinspeed 的 32.2% 不是"算法没写对"：可评估率 98.8%、
`Stable` 1968 帧，滤波器本身工作正常，缺的是观测自由度。

**剩余误差不是时间偏移**。对 sinspeed 做过外推补角比例的扫描（`aim_extrapolate_scale`
从 0 到 1.5，共 7 档）：

| scale | 0.0 | 0.3 | 0.6 | 0.8 | **1.0** | 1.2 | 1.5 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 命中率 | 3.9% | 16.1% | 30.5% | 32.9% | **32.2%** | 28.2% | 23.5% |

1.0 已在极值附近，继续加提前量反而变差。所以不能靠调 `prediction_latency` 解决，
瓶颈是切向误差带宽本身。

### 7.11 转速 ω 的估计：单一相位折叠拟合

对应 7.1 里 `yaw_rate` 这一维"由谁来测"。数学与推导单独写在
[omega 相位拟合说明](omega相位拟合说明.md)，这里只给结论。

**问题**。166 fps 下 10 rad/s × R=0.28 m 的切向位移只有 1.7 cm/帧，与 PnP 噪声
同量级，所以逐帧位置更新可以自洽地把静止目标推成 10 rad/s。早先的做法是维护一个
窗口、用四路证据（法向 Theil-Sen / 方位角 Theil-Sen / 同帧双板弦向 / 原始法向全配对）
各算一个斜率再融合。四路都形如"取若干对样本、算两两斜率、取中位数"，而窗口每前移
一帧，参与配对点集就整体换一次——**中位数因此是阶梯函数**，ω 曲线上的锯齿是这个
结构造成的，调参治不好。

**做法**。不再配对：窗口内所有同目标板观测的板相位一次性联合解一个参数

```
θ(t) = φ0 + ω·(t − t̄)，残差按 2π/N 折叠
```

换板造成的 ±2π/N 跳变由折叠内建消除，不需要"续接链 + 解缠 + 清窗"三件套。给定 ω
时 φ0 有闭式解（复数和的辐角 / N），于是只需要一维搜索 ω：粗网格 → 取峰 → 黄金
分割精化 → 谷底处按曲率是否显著决定要不要加二次项。输出的 ω 与 σ 通过原有的标量
卡尔曼观测（H = e₇）进 EKF，**EKF 本体一行未改**。

三个必须显式处理的坑（详见说明文档）：

* **先验自锁**。用二次罚 `C − λ(ω−ω_prev)²` 选峰会锁死：实测 8 rad/s 偏到 1 rad/s
  就再也回不来。改成线性罚（代价有界），既能压住相邻别名峰逐帧轮流赢，又允许真峰翻盘。
* **相位参考点**。"每帧各用自己的车心"会让参考点跟着车心随机游走，游走被原样读成
  转速（静止目标读出 0.5 rad/s）；"全窗用当前车心"在平移目标上读出 2.8 rad/s 的假
  斜率。最终让数据选：两档参考点各拟一次，取集中度 C 更高的那个。
* **断流与圆上一致性**。样本间隔 >0.20 s 就清窗（隔着遮挡接起来只会得到伪转速）；
  板心到车心距离与当前 R 相差 >0.10 m 的观测不入拟合（斜置副板、别的车的板）。

**结果**（`tools/compare_omega.py`，稳态段，首次 |ω|>0.5 后跳 1 s 瞬态）：

| 素材 | 指标 | 旧四路证据 | 相位拟合 |
| --- | --- | --- | --- |
| redrotate（四板自转） | ω 标准差 | 0.47 | **0.22** |
| | 帧间锯齿 std | 0.09 | **0.03** |
| | 符号翻转 / 掉零帧 | 0 / 0 | 0 / 0 |
| sinspeed（正弦变速） | ω 标准差 | 2.06 | **1.79** |
| | 帧间锯齿 std | 0.17 | 0.22 |
| | 符号翻转 / 掉零帧 | 0 / 0 | 0 / 0 |

合成的 G/H 场景同步复验（`ctest -R ekf_tracker`）：G 组 ω=2/4/6/8 rad/s 的估计
1.84/3.92/5.93/7.88（旧路径 1.98/3.98/5.95/7.99，都贴着真值），命中率
98/98/94/94%（旧路径 100/98/96/96%）；H 组静止 + 法向噪声 ±20° 的 ω 从 +0.10
降到 +0.01，平移场景 −0.20 → −0.10，慢转 1.5 rad/s 从 1.69 到 1.84。

**代价**。0.45 s 窗口对 2.3 s 周期的正弦必然做平均，sinspeed 谷底停在 2.5~3
（旧路径能到 0~1）。缩窗能救谷底但会抬高匀速场景的噪声，取舍写在说明文档 §7。

| 位姿解算 | 15 | 大小板 PnP、坐标系重排、孪生解消歧、异常拒绝齐备；重投影 0.57~2.63 px |
| EKF 跟踪与预测 | 20 | 静止/平移命中 99.8%；旋转 67.0%；高速单板 32.2%，瓶颈已定位 |
| Web Debug | 5 | 七类关键量全部可观测，且能导出做离线分析 |

四段实拍回放的命中率从 99.8% 到 32.2%，跨度很大，原因是场景难度不同而不是系统
不稳定。这个分布本身就是结论：相位可观测时（双板或多板）精度足够，单板高速旋转
时观测不足，需要从观测配置上解决，不是调参能补的。

## 10. 已知问题

> 测试状态（2026-10-31 更新）：`ctest -E camera_grab` **12 项全部通过**。
> 下面第 1 条记录的是这之前长期存在的 3 项失败及其修法，保留下来是因为
> 其中的分析（尤其 G 组 8 rad/s 的瞄准侧约束）仍是系统的真实现象。

1. **（已修复）3 项单元测试曾长期失败**（`ekf_model_convergence`、
   `ekf_init_contract`、`ekf_tracker`）。前两项是测试代码没跟上状态维度扩展：
   状态从 9 维加到 11 维后，测试夹具 `tests/ekf_test_support.hpp` 的 `truthState()`
   仍只用 9 个系数初始化 `Matrix<double,11,1>`，Eigen 的逗号初始化器断言崩溃。
   补齐后两项通过，属测试侧问题，不影响程序运行。

   第三项卡在 G 组 ω=8.0 rad/s 那一档"射击点落在朝相机那面的板"断言上：当时实测
   占比 90%，另两档（ω=2/4/6）是 100%/98%/100%。同一档 3 cm 命中率 96%、最近真板
   误差中位 0.015 m，说明是边界现象而非离散失败——8 rad/s 时板面转到背向相机的
   那几帧，瞄准点仍指向前一帧可见的板，属于 7.8 节"只允许瞄最近看见过的板"这条
   约束的直接后果。修 11 维夹具后同一断言通过。

   这三项在加 11 维状态之前就已经失败，用 `git stash` 回到基线对拍确认过。
   没有为了让输出好看去跳过它们，也没有放宽断言——修的是夹具。

2. **外参旋转未标定**。见 4.3。相对几何可用，绝对瞄准角有系统偏差。

3. **车体 yaw 只能确定到 2π/N**。N 块装甲板几何完全相同时，把 yaw 平移 2π/N 后
   板位集合不变，属于模型固有对称性，不是估计误差。不影响瞄准和角速度估计，
   但测试断言要按模 2π/N 写。

4. **单半径、等高模型**。前哨站那种交替高度/尺寸的目标需要按槽位扩展状态，
   `radius_2_m` 字段已预留但未启用。

5. **首帧半径依赖先验**。视场内只有一块板且目标静止时，半径取先验 0.28 m；
   与实际偏差大时中心估计会整体偏移。半径在锁定那一刻决定，之后只在重锁时才可能
   更新，这是 7.9 节 sinspeed 误差偏大的直接机制之一。

6. **关联是最近邻**。同色同编号的多车场景无法区分，依赖 `target_id` 过滤。
   全局最优分配在可见板数 ≤2 时没有收益。

7. **关联层的容差曾经是等比缩放**。`data_radius_tolerance = 0.35 × size_prior`
   在把先验从 0.20 调到 0.28 后，容差从 ±0.070 涨到 ±0.098，放行了圆拟合给出的
   0.3673（真值 0.28，偏 31%），锁定即歪。已改成
   `min(0.35 × size_prior, 0.08)`。这个 bug 的教训是"先验越准 → 容差越松 →
   越容易锁歪"，容差不能跟着先验等比放大。
