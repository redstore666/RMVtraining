## 0. 一句话结论

`俯视图显示的 ω` 和 `视频里板的实际转速` 对不上，**不是滤波器参数问题，是观测量本身的身份错了**：
一台车的 4 块装甲板编号完全相同（v4 里全是 id=3），逐帧"最近模型板"匹配在旋转时来回振荡，
相邻两帧的观测有 **18.6% 落在 0.2 m 以上**（其中 135/138 与 `best_slot` 变化同步）。
EKF 拿到的不是"某块板在圆周上匀速走"，而是"4 块板随机点名"。

在这种观测输入下，放大 Q 会让显示 ω 跟着跳变变成方波，缩小 Q 会让它恒等于 0 ——
**两种表现都叫"和真实转速不一致"，且都不是改参数能修的**。这正是三天补丁无效的原因。

旧实现取"偏差小者"等价于在 3.205 硬切，大板在 θ>37.5° 就被判小板，深度错 1.70 倍。

> 纯编号查表在本项目**不成立**——本项目 yolo11 属性表里 3/4/5/8 两种板都存在。
> 因此没有照搬，改为"编号只作约束、几何做单向证书、时域做收敛"。

## 2. 证据 A：D1 在实拍数据上零命中

`SIZE_POLICY=auto` 与 `SIZE_POLICY=legacy` 在同一视频上的判定**逐条完全一致**：

```
--- v4 auto   : 2460 dets        --- v4 legacy : 2460 dets
   1415 id=1 geo=L -> L             1415 id=1 geo=L -> L
   1044 id=3 geo=S -> S             1044 id=3 geo=S -> S
      1 id=5 geo=S -> S                1 id=5 geo=S -> S
--- v1 auto   : 1011 dets        --- v1 legacy : 1011 dets
    463 id=1 geo=L -> L              463 id=1 geo=L -> L
    534 id=3 geo=S -> S              534 id=3 geo=S -> S
     14 id=5 geo=S -> S               14 id=5 geo=S -> S
```

ratio 实测分布（决定为什么零命中）：

| 视频 | 编号 | n | min | p10 | p50 | p90 | max |
|---|---|---|---|---|---|---|---|
| v4 | id=1（大板） | 1415 | 4.10 | 4.20 | 4.28 | 4.39 | 4.49 |
| v4 | id=3（小板） | 1044 | 0.76 | 1.28 | 2.34 | 2.52 | 2.69 |
| v1 | id=1 | 463 | 3.36 | 3.56 | 3.68 | 3.79 | 3.94 |
| v1 | id=3 | 534 | 0.70 | 2.21 | 2.29 | 2.36 | 2.49 |

- id=1 的最小 ratio 是 3.36（v1）——**始终高于 3.00 证书线**，永远判大板，从不翻转。
- id=3 的最大 ratio 是 2.69——**始终低于证书线**，判小板，也从不翻转。
- 也就是说：v4/v1 里根本没有"大板转到侧向"的场景。原报告 §D1 的数学推导正确，
  但在这个数据集上**从未触发**。D1 是潜在风险，不是当前症状。

**同时证伪 D5（上一份报告的"素材板宽约 250 mm，与 135 mm 先验差 1.85 倍"）**：
v4 的 id=3 板 ratio 中位 2.34、最大 2.69，与**小板理论值 2.368 几乎重合**；
id=1 的 ratio 中位 4.28，与**大板理论值 4.035 一致**（略大 6%，属角点外扩）。
两块板都与 RM 标准尺寸自洽，不存在 1.85 倍偏差。D5 的来源是
`StudentTasks.cpp:626-631` 里那句"v4 的手写 3 板明显比 135mm 大，框宽中位 156px 对应 ~0.25m"
——那是个**过时的现场推测**，写成了注释后被后续分析当成了事实。
→ 前三天的 A/B 基线**没有**被板宽污染，可以放心复用。

## 3. 证据 B：观测流被换板跳变主导

取 v4 `--only-id 3` 的 741 对相邻观测（同 `obs_id`、`dt<20 ms`）：

| 指标 | 数值 |
|---|---|
| 帧间位移 p50 | **51 mm** |
| p90 | **361 mm** |
| p99 | 447 mm |
| >0.20 m（换板量级） | **138 次（18.6%）** |
| 0.05–0.20 m（既非物理运动也非整块换板） | 236 次（31.8%） |
| <20 mm（物理合理） | 174 次（23.5%） |

物理量级对照：ω≈7 rad/s、R≈0.2 m、166 fps → 切向位移 **8.4 mm/帧**。
实测中位数 51 mm 是它的 **6 倍**，p90 是 43 倍。

跳变归因（138 次大跳变）：

| 判据 | 计数 |
|---|---|
| 伴随 `best_slot` 变化 | **135 / 138** |
| `best_slot` 未变（纯深度噪声） | 3 |
| 其中 `slot 2→0` / `0→2`（相差 180°） | 93 |
| 其中 `2→3` / `1→3` 等（相差 90°） | 约 38 |

**135/138 的跳变与"关联到哪块模型板"同步发生**，说明位置突变不是测量噪声，
而是观测在 4 块同编号板之间来回点名。

> **自我更正（2026-10-25 晚）**：CSV 里的 `best_slot` 是**测试工具**按欧氏距离 argmin
> 算出的诊断量（`tests/test_camera_playback.cpp:1638-1656`），不是跟踪器内部的关联结果。
> 观测跳 0.4 m 之后最近板必然换一个，所以"同步"这一条**是同义反复，不构成独立证据**。
> 独立证据改为跳变幅度的离散性：`[0.20,0.26)` 档 0 个样本，峰值落在
> 0.26–0.32（2R·sin45°）与 0.32–0.44（2R）。详见
> `docs/量测与关联-三实现对照_2026-10-25.md` §4。结论方向不变。

## 4. 为什么这能解释"调了三天没效果"

1. **观测无身份**：4 块板编号相同，`ArmorDetection` 只带 `target_id`，不带"这是第几块板"。
2. **关联靠最近邻**：`best_slot = argmin ‖观测 − 模型板位置‖`。模型相位一旦有误差，
   最近邻就在两块板之间来回翻（实测 180° 与 90° 两种翻转）。
3. **每次翻转都喂进 EKF**：位置更新把 0.28~0.40 m 的阶跃当成真实位移，
   `ω` 为了解释这个阶跃只能乱给。
4. **参数在两种坏结果之间摆**：
   - Q 放大 → ω 跟随跳变 → 显示值变成方波/乱跳（"比实际快"）；
   - Q 缩小 → ω 完全不跟随 → 显示值恒 ≈0（"比实际慢"）；
   - 两者都是"和视频不一致"，且都改不动。
5. **历史补丁的作用点错了**：`applyProcessNoise()` 里已有 `SPIN_Q` 环境变量 +
   `adaptive_spin_q_enabled` 自适应（`RotatingArmorTracker.cpp:221-242`，注释写明
   "参考对齐 v2=400"），也就是说原报告的 layer1（Q 太小）**已经被补掉了**，
   而症状没变——这本身就是"病因不在 Q"的强证据。

## 6. 下一步（三个方案，待选）

**方案 A —— 关联层（推荐）**
在 `collectWorldObservations` / slot 匹配处加三条硬约束：
1. 角度门控：观测相对当前相位的偏差超过 ±45°+余量则拒绝，不做"最近邻硬塞"；
2. 双帧一致：同一 slot 需连续 2 帧落在门内才允许更新，抑制翻转；
3. 每板每帧至多一次更新（现在可能多块同 id 板同帧更新）。
代价：关联层单点改动，不碰模型与显示；能直接测「跳变率从 18.6% 降到多少」。

**方案 B —— 像素域测量（rmcs 路线）**
把 `ArmorDetection::corners` 直接当 4 维像素量测喂 EKF（字段与 rmcs `Armor2d` 完全同构），
绕开 3D 位置的身份歧义。代价大，收益是根治。

**方案 C —— 换 yolo11**
不解决关联问题（同编号仍是同编号），且 `docs/yolo11切换评估计划.md` 的 R1（滚转乱序，大板 θ<13.9°）未验证。
不建议作为第一步。
