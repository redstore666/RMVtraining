## 0. 结论

**不是。** 两个主要参考实现走的是两条完全不同的路：

| | rmcs_auto_aim_v2 | sp_vision_25 |
|---|---|---|
| 量测形式 | **像素**（灯条上/下端点 xy） | **球坐标 + 板面法向角**（yaw, pitch, distance, armor_angle） |
| 量测维度 | 4 / 灯条 | 4 / 装甲板 |
| 关联依据 | 解析可见性模型 + **图像 x 排序循环递推** | **角度误差最小**（位置只做预筛） |
| 部分可见 | 支持（单灯条也能更新） | 不支持（必须整板） |

**共同点只有一条**：都不允许"3D 位置距离"当关联的主判据。
这才是防 180° 翻转的关键，像素/球坐标只是量测的表达方式。

## 1. rmcs_auto_aim_v2 —— 真正的像素域

### 1.1 量测就是像素
`src/module/tracker/model/robot.hpp:88`
```cpp
// 观测噪声（像素噪声）
double noise_observation = 40.0;
```

`src/module/tracker/model/robot.cpp:439-462`（`update(upper, lower, id)`）
```cpp
auto innovation = Eigen::Vector4d { };
innovation << upper.x() - pred_upper.x(), upper.y() - pred_upper.y(),
    lower.x() - pred_lower.x(), lower.y() - pred_lower.y();   // 4 维像素残差
const auto jacobian = make_observation_jacobian(id);           // 4×11 数值 Jacobian
```
Jacobian 是数值差分得到的（`robot.cpp:234` 起，`kEpsilon = 1e-4`），
不是解析式——因为"投影 + 车体几何"求导太脏，数值差分 11 维 × 4 行完全跑得动。

### 1.2 关联靠可见性模型，不是最近邻
`src/module/tracker/model/robot.cpp:191-206`
```cpp
const auto yaw = std::acos(std::clamp(armor_face.dot(armor_to_cam), -1.0, 1.0));
if (yaw >= yaw_part_max) continue;                 // ≥90° 整块不可见
if (yaw < yaw_full_max) {                          // <60° 两条灯条都可见
  visible[left_id] = true;  visible[right_id] = true;
} else {                                           // 60~90° 只可见一条
  visible[on_plus_y ? right_id : left_id] = true;
}
```

### 1.3 关联靠图像顺序递推（最关键的 15 行）
`src/module/tracker/model/robot.cpp:600-616`
```cpp
std::ranges::sort(sorted,
    [](const SortedEntry& a, const SortedEntry& b) { return a.upper.x() < b.upper.x(); });
// 锚定位 → 向两侧递推
sorted[anchor_left].assigned_id  = anchor_armor_id * 2;
sorted[anchor_right].assigned_id = anchor_armor_id * 2 + 1;
for (std::size_t i = anchor_left + 1; i < sorted.size(); ++i)
    sorted[i].assigned_id = (sorted[i - 1].assigned_id + 1) % 8;
for (std::size_t i = anchor_left; i > 0; --i)
    sorted[i - 1].assigned_id = (sorted[i].assigned_id - 1 + 8) % 8;
```
灯条绕车一圈，投到图像上必然是**角序 = 索引序**。所以：先用一个高置信锚点定住，
再按 x 排序向左右各递推 ±1（模 8）。**结构上不可能出现 180° 翻转**——
相邻灯条的 id 只能差 1，不允许跳到对面。

Step 1 的锚点选择（`robot.cpp:549-570`）仍用像素误差和最小，但只在
`visible[]` 为真的候选里选，把搜索空间从 4 块压到 1~2 块。

## 2. sp_vision_25 —— 不是像素

`tasks/auto_aim/target.cpp:222`
```cpp
const Eigen::VectorXd &ypd = armor.ypd_in_world;
const Eigen::VectorXd &ypr = armor.ypr_in_world;
Eigen::VectorXd z{{ypd[0], ypd[1], ypd[2], ypr[0]}};   // yaw, pitch, distance, 板面法向角
ekf_.update(z, H, R, h, z_subtract);
```
四维里**第 4 维是板面法向角**——这一维直接把"观测到的是哪一面"告诉滤波器，
ω 的观测信息主要从这里来。

### 关联：角度优先，位置只做预筛
`tasks/auto_aim/target.cpp:142-166`
```cpp
// 取前3个 distance 最小的装甲板
for (int i = 0; i < 3; i++) {
  auto angle_error = std::abs(tools::limit_rad(armor.ypr_in_world[0] - xyza[3])) +
                     std::abs(tools::limit_rad(armor.ypd_in_world[0] - ypd[0]));

}
```
注意结构：`distance` **只用来筛出 3 个候选**，真正排序的是 `angle_error`。
位置距离从头到尾没进过打分函数。

## 3. 本项目的现状（关键：两条路都已打过补丁）

### 3.1 4 维球坐标量测已经实现了
- `student/include/RotatingArmorModel.hpp:23` `constexpr int kSphericalMeasurementDim = 4;`
  注释写明"球坐标量测量 (yaw, pitch, distance) + 板面法向角，共 4 维"
- `student/src/RotatingArmorModel.cpp:103` `sphericalMeasurement(...)`
- `student/src/RotatingArmorEkf.cpp:306-314` `update()` 已在用它算 `h` 与 `h_jacobian`

但它**默认关闭**，`student/src/RotatingArmorEkf.cpp:290-296`：
```cpp
static const bool spherical_on_by_env = std::getenv("EKF_SPHERICAL") != nullptr;
if (!config_.spherical_measurement_enabled && !spherical_on_by_env) {
    // 球坐标版本在 v4 上更快但会把高速自转的瞄准点打到相邻板上（见 docs）。
    return updateCartesian(observation, plate_slot);
}
```
→ 已经试过，结果是"打到相邻板上"。**这正是关联问题在另一种量测下的同一个症状。**

### 3.2 角度优先关联也已经实现了
`student/src/RotatingArmorTracker.cpp:2777-2792`
```cpp
const double normal_err = std::fabs(wrapToPi(world[i].yaw - face_yaw));
const double obs_bearing  = std::atan2(world[i].position.y(), world[i].position.x());
const double pred_bearing = std::atan2(predicted.y(), predicted.x());
const double bearing_err  = std::fabs(wrapToPi(obs_bearing - pred_bearing));
score += config_.association_angle_weight_m_per_rad * (normal_err + bearing_err);
```
默认 `association_angle_weight_m_per_rad = 0.30`（`RotatingArmorTracker.hpp:242`）。

按 0.30 m/rad 估算，180° 错配时应多付 `0.30 × π = 0.94 m`，
远大于两板间距 0.40~0.45 m —— **理论上应该压死翻转**。但它仍在翻。
说明某个前置条件没成立（最可能：`world[i].has_yaw == false` 时整个角度项被跳过，
此时 `score = distance`，退化成纯最近邻）。

### 3.3 层边界：像素域不是局部改动
`student/include/RotatingArmorTracker.hpp:742-752`
```cpp
struct WorldObservation {
    Eigen::Vector3d position{0.0, 0.0, 0.0};
    bool has_yaw{false};
    double yaw{0.0};
    int target_id{0};
    ArmorSize size{ArmorSize::Small};
    double sigma_position_m{0.03};
};
```
tracker 层**完全没有相机内参、也没有角点**（`RotatingArmorTracker.hpp` 里搜不到
`CameraParameters` / `camera_matrix` / `distortion`）。像素域改造要：
穿过 `StudentTasks` → `Tracker` 的层边界补内参 + 4 灯条点 + 投影函数 + 数值 Jacobian
+ 图像顺序关联，估计 400~600 行，且要重标定全部合成回归契约。

## 4. 对上一份报告的一处自我更正

`docs/转速不一致-实测证伪与关联层定位_2026-10-25.md` §3 用
"138 次大跳变中 135 次与 `best_slot` 变化同步"作为"身份错"的证据。
**这个相关部分是同义反复**：CSV 里的 `best_slot` 是测试工具按欧氏距离
argmin 算出来的诊断量（`tests/test_camera_playback.cpp:1638-1656`），
观测跳 0.4 m 之后最近板必然换一个 —— 不构成独立证据。

仍然成立的部分：
- 跳变幅度**不连续**，在 `[0.20, 0.26)` 这一档是 **0 个样本**，两侧却各有峰值：

  | 区间 (m) | 计数 | 对应几何量 |
  |---|---|---|
  | 0.05–0.10 | 205 | 多帧间隙 / 小角度换板（R 拟合 0.164 时 2R·sin(22.5°)=0.126） |
  | 0.10–0.20 | 31 | 同上 |
  | **0.20–0.26** | **0** | **空档** |
  | 0.26–0.32 | 8 | 2R·sin45° ≈ 0.232（邻板） |
  | 0.32–0.38 | 76 | 2R ≈ 0.328（对面板） |
  | 0.38–0.44 | 43 | 同上 |
  | 0.44–0.60 | 11 | 跨两块板 |

  连续噪声不会在 0.20–0.26 留空档、却在 2R 与 2R·sin45° 处堆峰。
- 741 对相邻观测里只有 **23.5%** 落在物理运动量级（<20 mm）内，
  其余 76.5% 无法用"目标在匀速转动"解释。

结论方向不变（观测流被换板跳变主导），但证据强度要按上面修正后的口径引用。
