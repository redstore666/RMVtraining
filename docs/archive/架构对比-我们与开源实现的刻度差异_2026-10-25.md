# 架构对比：我们 vs sp_vision_25 / rmcs_auto_aim_v2 —— 该不该进入肉眼调参阶段

**结论：不该。** 我们的状态定义、Q 结构、P0 结构跟两家参考**完全同构**，
但三个关键量的**刻度全都错在 25~240 倍量级**。也就是说现在连"同一个坐标系"都没对齐，
在这个前提下调 Q/P 等于在两个错误刻度之间来回跳——这也是过去三天所有结论
（"Q 是死胡同""σ 不能动"）的共同来源。

首次在参考刻度上成对跑一遍，就拿到历史最好结果：v4 ≤5cm **73.15% → 86.85%**，
v1 **47.02% → 51.28%**，两个片段同时涨。

## 一、架构对比：同构，不需要重写

| 维度 | 本项目 | sp_vision_25 | rmcs_auto_aim_v2 |
|---|---|---|---|
| 状态 | 11 维 `cx vx cy vy z vz a w r l h` | 11 维，**同一顺序** | 11 维，**同一顺序** |
| 过程噪声结构 | 连续白加速度 `q·[[dt³/3, dt²/2],[dt²/2, dt]]` | 分段白噪声 `v·[[dt⁴/4, dt³/2],[dt³/2, dt²]]` | 每帧常量对角 |
| 角度量测 | 独立标量 `updateFaceYawForSlot` | 与位置**联合** 4 维 `(y, p, d, plate_a)` | 像素域 4 维（重投影） |
| 换板/身份 | `identity_posture` 后验（S2，默认关） | 距离排序前 3 + 最小角误差 + `Voter` | `id±1 mod N` + `Jumped` 标记 |
| 收敛/发散判定 | `phase_resolved` + 状态机 | `converged()` / `diverged()` | 协方差迹阈值 |
| 预测外推 | 同 | 同 | 同 |

**结论：状态空间、可观测性、预测模型这三层没有架构差异。** 之前担心的"要不要重写成
像素域"只有 rmcs 一家这么做，而 sp_vision_25 用位姿量测拿了 701 star 且在用，
说明位姿路线本身没问题。

## 二、真正的差异：三个量的刻度（这是本次最重要的发现）

### 2.1 角加速度 Q 的离散化口径不同 → 差 241 倍

| 实现 | 公式 | dt=1/166 时的 Q(7,7) |
|---|---|---|
| sp_vision_25 | `Q_ω = v2 · dt²`，v2 = **400** | **0.0145** |
| rmcs | 每帧常量 `noise_rotation_speed = 1.0` | 1.0 |
| **本项目（现状）** | `Q_ω = q · dt`，q = **0.01** | **6.02e-5** |

`6.02e-5 / 0.0145 = 1/241`。**我们的 Q_ω 比最保守的参考还小 241 倍。**

§四十二 当时以为"把 v2 抬到 400 就对齐参考了"，但我们的离散化是 `q·dt`，
参考是 `v2·dt²`——同一个数字在两种口径下差 `1/dt = 166` 倍。
所以那次"抬到 400"实际上等于参考口径的 v2 ≈ 66400，**过松 166 倍**；
而默认的 0.01 等于 v2 ≈ 1.66，**过刚 241 倍**。
历史上每一次调 Q 都是在这两个错误刻度之间跳，**从来没有落在 2.4（=400·dt）附近**。

### 2.2 角度量测 σ：8 倍

| 实现 | σ_angle | R_angle |
|---|---|---|
| sp_vision_25 | `√(log(|d|+1)/200 + 9e-2)` ≈ **0.31 rad**（17°） | 0.0955 rad² |
| **本项目** | **2.5 rad**（143°） | 6.25 rad² |

差 65 倍方差、8 倍 σ。等于告诉滤波器"这条量测基本别信"，而它却是 ω 的唯一来源。

### 2.3 初始协方差 P0：两个方向都反

| 量 | 本项目 | sp_vision_25 | rmcs | 判定 |
|---|---|---|---|---|
| P0(angle) | **π² = 9.87**（σ=3.14） | **0.4**（σ=0.63） | **0.4** | 我们对角度**过度**不确定 25 倍 |
| P0(ω) | **9**（σ=3.0） | **100**（σ=10） | **100** | 我们对转速**过度**自信 11 倍 |

两家参考给出**完全相同**的 `0.4 / 100` —— 这说明它不是"调"出来的，
而是物理先验：不知道车在怎么转，所以允许 ±10 rad/s；但车体朝向大致知道，所以 σ=0.63。

我们的组合是：角度当作完全未知（σ=π）、转速当作已知（σ=3）、然后又不让它变（Q 过刚 241 倍）。
这三条**指向同一个行为**：相位被位置量测硬拽、ω 冻死——正好是我们测到的现象。

## 三、首次在参考刻度上的实测（v4 旋转 / v1 近静止）

`--id-posterior 1` = 打开 S2 板身份后验（我们的 Voter 对应物）。

| 配置 | v4 ≤5cm | v1 ≤5cm |
|---|---|---|
| 现状（q=0.01，σ=2.5，身份关） | 73.15% | 47.02% |
| q=4，σ=0.31，身份**关** | 78.52% | 36.38% |
| **q=4，σ=0.31，身份开** | **86.85%** | **51.28%** |
| q=8，σ=0.31，身份开 | 88.19% | 29.15% |
| q=2.4（严格=参考 v2=400），σ=0.31，身份开 | 79.60% | 40.00% |
| q=4，σ 自适应（斜视角），身份关 | 72.89% | 45.96% |

读法：
1. **刻度对齐本身就能涨**（q 从 0.01 到 4，同一份代码只换数）：v4 +5.4 点；
2. **身份后验是第二个放大器**：v4 78.5 → 86.9、v1 36.4 → 51.3。
   原因很直接——σ 收小之后角度量测真的在起作用，一旦槽位判错就硬拽 ±90°；
   身份判对，小 σ 才是安全的。**σ 和身份是耦合的，必须一起改。**
3. q=8 已经把 v1 打崩（29.15），说明 q 的有效区间就在 2~5，不是"越大越好"。

## 四、还差的不是参数，是"联合更新"这一块

在 `q=2.4 / σ=0.31` 下 `ekf_tracker` 的 G 组（ω=6、8 rad/s 预测点）会红：
预测点偏一块板（0.35 m）、3cm 命中率掉到 43%。

而 sp_vision_25 用同样的 Q 量级却能打比赛，差别在这两处：

1. **量测是 4 维联合更新**：`z = (y, p, d, plate_angle)`，一个 H、一个 R、一次更新，
   角度和位置在同一个线性化点上做；我们是"先位置、再单独更新角度"，
   角度残差是在位置更新**之后**的状态上算的，等效 R 与参考不一致。
2. **R 与距离/斜视角耦合**：参考的 `R_plate = log(|d|+1)/200 + 9e-2`，
   远距离/斜视时自动放大；我们是常量。

这两条都不是"调参"，是量测层的结构。**这才是下一个该动的地方**，
而且我们代码里已经有对应开关（`angle_state_obliquity_sigma`，实测中性偏负，说明
公式本身不是参考那条，需要照着 `log(|d|+1)/200+9e-2` 重写）。

## 五、什么情况下才算"进入肉眼调参阶段"

给出可判定的门槛，不到就不许调：

- [ ] Q_ω 落在参考刻度带内：`q ∈ [2, 5]`（等价 v2 ∈ [330, 830]），而不是 0.01 或 400；
- [ ] σ_angle 由公式给出（距离/斜视角），不是手工常量；
- [ ] 身份后验默认开，且 `ekf_tracker` G/H 全绿；
- [ ] 上面三条同时成立后，v4/v1 的 ≤5cm 仍然差 **>10 个百分点**，或 |ω|/真值仍在
      0.9~1.1 之外 —— 这时才轮到"微调最后 10~20%"。

现在这三条一条都不满足，所以答案是不进。
