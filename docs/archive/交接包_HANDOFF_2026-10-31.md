## 6. 已经确证的事实（含**已证伪**的方向，别重做）

### 6.1 症状是"冻住 + 抖"，不是"转得慢"

`yaw` 每帧变化中位 **0.01°**、p90 6.4°、单帧跳 >5° 占 **11.3 %**、20 s 净转角 **0°**。
用户说"同一个颜色的板子只是振荡"——就是这条曲线的观感。

### 6.2 三个结构性障碍

1. **单板位置观测几乎不含绝对相位**。四板 90° 对称，相位只有 mod 90° 可辨识；一次单板更新只能挪一点，然后卡住。
2. **双板整车解被 45° 偏置挡死**。`pair_body_solve_enabled` 库默认 `false`；`pair_body_max_phase_error_rad{0.35}`（20°），而实拍法向与模型槽位差**稳定 45°** → 1600 帧只成功 11 次。
   **但把门限放宽到 0.95 rad 让它狂跑（38232 次）后指标反而变差**（`|lag|<20%` 53%→30%）→ 不是"少了一道门"，是解出来的相位本身不对。
3. **转速窗口被拒**。改前 85 % 是 "sigma 过大"（相位折叠没解缠），加物理闸门后主因变成"超物理闸门"（斜率 >12 rad/s）→ 斜率是伪值，来源是**极点（车心）误差 / 续接到别的板 / R 崩**。

### 6.3 已证伪的方案（都跑过、都回退干净）

| 方案 | 结果 |
| --- | --- |
| 极点 = 窗口内"车心轨迹线性拟合" | v4 伪值 +19~34 → −2.4~+0.5，但 `test_multi_target` 场景 B（静止车锁定头 0.35 s 车心在收敛）把"收敛"读成平移，`bear≈+3.0 rad/s` → 挂 |
| 按拟合残差在"拟合极点 / 每帧车心"之间切换 | B 恢复，H 组"静止+噪声法向"0.07→−1.28（板心与车心同源，errors-in-variables） |
| 一律拟合 + 上锁 0.4 s 内不估速 | G 组 3 项挂 |
| NIS 兜底更新（连 miss 3 帧接受最近候选 + 噪声放大） | 2643 帧只触发 0~3 次，`updates==0` 反而 58%→64% |
| `rate_from_residual`（PLL） | ω 顶到 12 上限、`R` 塌 0.155、`|lag|<20°` 24.9% → 只会"乱转" |
| `tracklet_rate` | 与 baseline 无差别 |
| 相位"折回拟合线再估斜率"（第二遍解缠） | `dYaw` p90 6.36→7.23、净转 0→+26°：**没用**（斜率偏差不是整段周期偏移造成的） |
| 双板解门限放宽到 0.95 rad | 见上，更差 |

### 6.5 其它已知缺陷（顺手看到的）

- **`R` 会在锁定初期/坏时刻崩到 clamp 下限 0.152**（正常 0.25~0.27），此时板离"车心"只有 0.15 m，方位角全是噪声；同帧 `ω` 会冲到 +8~+10。这可能就是"超物理闸门"那 399 次的主要来源，**优先级很高**。
- 静止车上 `phase_lag` 恒 **−45.0°±2.5**、`normal-bear` 中位 +14.6°（p90 +45.6°）：观测法向有固定偏置，任何用绝对法向的相位校正都得先减掉它。
- 空帧：`pin_poses==0` 占 39.6 %（被选车这一帧根本没被检出）；Idle 阶段 100 % 零更新、Unstable 71 %。稳态（Stable）其实 80 % 帧有更新 —— 空帧大头在**重捕/锁定**，不在稳态滤波。
- `get_pic()` 用 `MV_CC_GetOneFrameTimeout` 取的是**队列最旧的一帧**，处理慢就会累积延迟（生产 `main.cpp` 也走这条路，本次没动）。
- 相机内参现在是**车上相机**（`config/camera.yaml`：`fx 1782.6 fy 1784.3 cx 749.4 cy 574.7`，dist `[-3.570e-02, -1.533e-01, 0, 0, 1.1905]`）；2 号机在注释里。外参 `R` 仍是单位阵占位、`t=[6.711e-02, 0, 5.150e-02]` —— **实车上这两个必须重测**，否则"打中装甲板"无从谈起。

## 8. 环境坑（都踩过，别再踩）

1. **bash 调用之间的进程**：`&` 起的进程会跨调用存活但 `ps` 看不见、`kill` 不掉 → 端口被旧二进制占着、curl 抓到旧数据（曾误判"新日志键没生效"）。**一调用内起停 + 随机端口**。
2. `pkill -f "test_camera_system ..."` 会把自己这条 bash 命令一起杀掉（exit 143）→ 用 `$!` + `kill $PID`。
3. **编译和运行分开两次 bash 调用**。写成 `cmake --build && TRACK_DEBUG=... &` 会把整条链后台化、日志不生成。
4. `tmp/system_mini_*.png` **不会自动清**，上一次的会被误认为本次的（曾把 v4 的帧当 v1 的看）→ 先 `rm`。
5. `ctest`：`camera_grab` 恒失败（环境无相机），其余应全绿。`ekf_multi_target` 在机器负载高时可能因时序抖动失败，先看 `load average`。
6. 机器 `load average` 到 20+ 时 `fps_loop`/`detect_ms` 不可比（`detect` 能到 264 ms）；**比例类指标（`dYaw`、`|lag|<20%`、`|ω|≥5%`）不受影响**，比较 A/B 时优先看它们。
7. matplotlib 没中文字体：`docs/figures/make_v4_webdebug_figs.py` 顶部已设 `Noto Sans CJK JP`；跑的时候 `MPLCONFIGDIR=/tmp/mpl`。
8. `/tmp` 在两次 bash 调用之间可能被清 → 中间产物写 `tmp/` 或 `build/`。
