# YOLOv5 → YOLO11 切换效果评估计划

| 项目 | 内容 |
|---|---|
| 版本 | v0.1（草案，待评审） |
| 状态 | **仅计划，不执行** |
| 适用代码 | 当前 `main` 工作区（`armor_detect` / `ArmorDetectorNet`） |
| 核心问题 | 是否值得把默认检测模型从 `models/yolov5_640x480.xml` 换成 `models/yolo11.xml`？ |
| 产出 | 一份可复现的配对 A/B 报告 + 一个二选一的决策 + 可回滚的切换开关 |

---

## 0. 一句话结论（先看这里）

**现在还不能拍板切换，缺的不是模型文件，而是证据。** 仓库里 `yolo11` 的加载与解码路径已经写完，但从未在任何实拍帧上做过配对对比；而且这两个产物之间至少混着三个变量——输入尺寸（640x640 vs 640x480）、量化（yolo11 是 INT8 FakeQuantize 导出，yolov5 是 FP16 权重）、置信度语义（objectness vs 38 类分数）。本计划的作用就是**把这几个变量拆开、逐项量化**，用同一批帧、同一套后处理、同一台机器给出"切 / 不切"的判定，并保留一条随时能回退的开关。

---

## 1. 背景与现状

### 1.1 链路

相机取流 → `armor_detect`（NN 四点检测）→ `armor_solve`（PnP + 孪生解消歧）→ `ekf_predict`（旋转目标 EKF）。检测层换模型，对下游唯一的接口是 `std::vector<ArmorDetection>`（四角点 + 颜色 + 编号 + 大小 + 置信度）。

### 1.2 两个产物的差异（这是实验设计的地基）

| 维度 | yolov5（当前默认） | yolo11（备选） |
|---|---|---|
| 文件 | `models/yolov5_640x480.xml`（默认）/ `yolov5.xml` | `models/yolo11.xml` |
| 输入 | 640x480（另有 640x640 / 512x512 / 512x384 变体） | **仅 640x640** |
| 输出 | `1x25200x22`：[4 关键点(TL,BL,BR,TR) \| objectness \| 4 颜色 \| 9 编号] | `1x50x8400`：transpose 后 [xywh \| 38 类 \| 8 关键点] |
| 大小判定 | 几何比例（外缘宽/条高 ≈ 2.37 / 4.04） | 38 类里自带（颜色 × 编号 × 大小） |
| 置信度语义 | objectness(sigmoid) | 38 类 argmax 分数，**无 objectness** |
| 量化 | FP16 权重，无 FakeQuantize | **110 个 FakeQuantize 节点（INT8 量化导出）** |
| 关键点→角点 | 固定列序 TL,BL,BR,TR | **按 y 排序分组 + 组内按 x 排序** |
| 实拍 A/B | 有（历史记录） | **无，一次都没跑过** |
| 默认启用 | 是 | 否（需 `RMV_DET_MODEL=yolo11`） |

`models/README.md` 对此的描述是"解码器已实现但未经实拍 A/B"，本计划就是把这句话补完。

### 1.3 已经暴露的两个具体风险（不是猜测，是读代码读出来的）

**R1 — yolo11 的角点分组在滚转下有数学上限。**
`decodeYolo11` 把 4 个关键点按 y 排序，前 2 个当 top、后 2 个当 bottom。对 w×h 的矩形，绕光轴滚转 θ 后，"上边两点 y 都小于下边两点"成立的条件是 `tanθ < h/w`：

- 小板 135×57 mm → **θ < 22.9°**
- 大板 230×57 mm → **θ < 13.9°**

超过这个角度，上边的一点会被分到下半组，四个角点被**乱序**返回；`armor_solve` 拿乱序角点做 PnP，重投影会炸、姿态会翻。yolov5 是固定通道顺序，不受影响。实车/手持云台滚转到 15°~25° 完全正常，所以这不是理论边角料，**是必须专门测的一条**。

**R2 — 两个产物不是同一类东西。**
yolo11 是 INT8 量化 IR（110 个 FQ），yolov5 是 FP16。所以测出来的差异是"可部署产物的差异"，不能直接归因为"架构更优"。计划里如实记录该 confound，不宣称架构结论。

### 1.4 已有的测量能力与缺口

| 已有 | 缺口 |
|---|---|
| `test_detect`（单图、可存图） | 无 GT，只能眼看 |
| `test_batch`（目录、"检出率"=有 ≥1 检测的帧占比） | **无真值**；多目标场景口径不严谨；只有汇总没有逐帧明细 |
| `test_solve`（PnP 距离/yaw/重投影） | 只喂固定点，不接检测输出 |
| `test_camera_live`（fps_cam / fps_nodisp） | 需要相机；不能离线重放录像 |
| `bench_detect`（拆 预处理/infer/decode） | **AB 交替段只有 3 个 yolov5 变体，没有 yolo11** |
| `tmp/*.avi` 三段实拍（1440×1080） | 没有帧级标注 |

→ 本计划的核心新增物是**一个配对跑批工具 + 一个标注工具 + 一个统计脚本**，其余全部复用现有代码。

## 2. 目标与非目标

### 2.1 目标

1. 在**同一批帧**上定量对比 yolov5@640x480 与 yolo11@640x640 的检出、定位、分类、延迟、稳定性。
2. 判定 R1 是否真实发生（滚转乱序），若发生给出修复方案与修复后的复测数据。
3. 给出一句可执行的结论："默认模型保持 yolov5" 或 "默认切 yolo11，yolov5 保留为 env 回退"。
4. 产出的脚本/数据/报告可被别人复跑，作为评分加分项（`docs/验收与评分.md` 明确认可"可复现实验对比"）。

### 2.2 非目标

- ❌ 不重训任何模型（无数据集、无 `.pt`，另立项目）
- ❌ 不改 EKF / 控制器 / 串口协议
- ❌ 不动相机标定与外参（A/B 是相对比较，外参占位不影响结论）
- ❌ 不追求绝对精度数字（合成图与实拍混用没有意义）
- ❌ 不在数据不足时"先切了再说"

## 4. 评测口径

### 4.1 配对原则（不可妥协的几条）

1. **同帧**：两个模型喂完全相同的图像（同一份 PNG，不是各自去 decode 视频——解码器差异会引入噪声）。
2. **同后处理**：`ab_detect` 内部对两个模型施加与 `armorDetectNn` 完全一致的生产过滤（敌方颜色、`kNnMinConfidence=0.7`、四角点在图内），保证测的是"线上会看到的结果"。
3. **同进程交替**：两个模型在同一个进程里 A/B 轮流跑（机器有负载时，只有交替测量可信），只报**比值**与配对差值，不报跨天的绝对值。
4. **分阈值语义**：yolo11 没有 objectness，0.7 在两边不是同一个意思。因此除"生产工作点 0.7"外，再报一条**等精确率**曲线（把两边的 precision 拉到同一水平再比 recall），否则结论会被阈值偷走。
5. **报告效应量与置信区间**：不写"看起来差不多"，写"配对差值 +1.2pp，95% CI [-0.4, +2.8]"。

### 4.2 指标定义

| 指标 | 定义 | 聚合 | 数据要求 |
|---|---|---|---|
| 每板召回率 | 匹配上的 GT 装甲板 / GT 装甲板总数 | 总体 + 按距离桶/大小/颜色 | Tier A+B |
| 每帧误检数 | 未匹配任何 GT 的检测数 / 帧数 | 总体 | Tier A+B |
| 匹配规则 | 检测中心与 GT 中心的距离 < 0.5×GT 边长，且唯一（按置信度贪心） | — | — |
| 角点误差 | 4 个角点的欧氏误差均值（px），同时报归一化值（÷GT 板宽） | 中位 + P90 | Tier A |
| `quad_ok` 率 | 返回的四边形是否凸、长边是否为 0-1 与 2-3（即 len(c0,c1) ≈ len(c2,c3) 且 len(c1,c2) ≈ len(c3,c0)，20% 容差） | 总体 + 按滚转桶 | **仅需图像，无需 GT** |
| 大小/编号/颜色准确率 | 在匹配上的样本里，三项分别对的比例 | 总体 + 按距离桶 | Tier A+B |
| 重投影误差 | 用检测角点 + `armor_solve` 的 PnP，重投影到图像的 RMS（px） | 中位 + P90 | Tier A |
| 距离误差 | `abs(PnP 距离 − GT 角点 PnP 距离) / GT 距离` | 中位 + P90 | Tier A |
| 延迟 | `detect()` 端到端（ms）与拆分的 pre/infer/decode | 中位 + p10 + p90 | 所有帧 |
| 端到端 | `test_camera_live --no-display` 的 `fps_nodisp` | 60s 均值 | 实机 |
| 稳定性 | 500 帧无崩溃/无 NaN/无越界；丢检连续帧数 | 计数 | 所有帧 |

> 角点误差要求 GT 精度高于被测差异。若同一帧重复标注的角点标准差 > 1.5px，则**远距小板只比 PnP/抖动类指标，不比角点 RMSE**（标注噪声会淹没差异）。

### 4.3 切换判定门槛

只有全部"必须"项通过才切默认：

| 项 | 类型 | 通过条件 |
|---|---|---|
| 每板召回（thr=0.7） | 必须 | Δ ≥ −1.0pp；且每个距离桶 Δ ≥ −3.0pp |
| 每帧误检 | 必须 | 不高于基线 +0.5 个/帧 |
| 角点误差 中位/P90 | 必须 | 中位劣化 ≤ 0.5px 且 P90 劣化 ≤ 1.0px |
| 颜色/敌方过滤 | 必须 | Δ ≥ −0.5pp，无新增错误阵营 |
| `detect()` 中位延迟 | 必须 | ≤ 基线 × 1.10 |
| `fps_nodisp` | 必须 | ≥ 基线 × 0.95 |
| 稳定性（500 帧） | 必须 | 无崩溃/NaN/越界；连续丢检不劣于基线 +2 帧 |
| 大小分类准确率 | 重要 | ≥ 基线（期望提升） |
| 编号准确率 | 重要 | Δ ≥ −1.0pp |
| `quad_ok` 率（滚转 ≤30°） | 必须 | 不低于 yolov5 对照（yolov5 固定列序，理论上 100%；以它为噪声基准）；滚转 ≥15° 的分桶里必须 100%，否则 R1 成立，先修再测 |

判定结果与处置：

- **全部通过** → 切默认（改 `nnDetector` 的默认 `kind` 或 `RMV_DET_MODEL` 缺省值），yolov5 保留为 env 回退，两个模型文件都留在 `models/`。
- **精度全过、仅延迟不过** → 进入 S3.3：尝试 yolo11@640x480；达标则切，否则 yolo11 仅作可选。
- **任一精度"必须"项不过** → **不切**，yolo11 保持 env 可选；若失败项是 H4，则先修 decode（修复本身对生产有益），修完单独跑一轮复测再判定。
- **数据量不足**（如 Tier A < 60 帧）→ 只写"初步结论 + 待补数据"，不允许下切换结论。

### 5.1 素材

> `tmp/` 在 `.gitignore` 里。**抽出的帧要落到 `tests/data/ab_yolo11/frames/`**，否则报告不可复现。

### 5.2 抽样：分层，不是等间隔

先按历史口径每 30 帧抽一个候选（红 64 / 蓝 141），再从中**按桶补齐**：

| 分层维度 | 桶 | 目标帧数（Tier A） |
|---|---|---|
| 距离 | 近 1–3m / 中 3–6m / 远 6–10m | 35 / 35 / 30 |
| 滚转（目视估计） | 0° / ±15° / ±30° | 70 / 20 / 10 |
| 板型 | 小板 / 大板 | 70 / 30 |
| 颜色 | 红 / 蓝 | 50 / 50 |
| 遮挡/边缘 | 有无遮挡、出画边缘 | 各 15 |

> 距离与滚转先在 `ab_extract` 里粗标（用 yolov5 的 PnP 距离做初值、人工改桶），不追求精确，只用于分层。

### 5.3 三层真值

| 层 | 帧数 | 内容 | 单帧成本 | 用途 |
|---|---|---|---|---|
| **Tier A** | 100 | 4 角点 + 颜色 + 编号 + 大小 + 距离 + 滚转 | ~30s（检测初始化后多为确认） | 角点误差、PnP、大小/编号 |
| **Tier B** | 200 | 只标"有几块、每块颜色/编号/大小"（不点角点） | ~6s | 召回/误检/分类（样本量） |
| **Tier C** | 全部 | 无 GT | 0 | 延迟、`quad_ok`、稳定性、丢检 |

Tier A 的 100 帧从 Tier B 的 200 帧里抽 50 帧组成嵌套，另 50 帧独立抽，避免"A 的分布 = B 的分布"造成过拟合。

### 5.4 标注流程与防偏

1. 工具：`tools/label_armor.py`（OpenCV，纯 Python + numpy，不依赖 OpenVINO）。
   - 打开图 → 右侧 4× 放大窗跟随鼠标 → 依次点 TL/TR/BR/BL → 回车存 JSON。
   - `--init <csv>` 用某模型的高置信检测**预填**四角点，标注者只需拖动修正；`n` 删除、`d` 丢弃该帧。
   - 快捷键：`1/2` 小/大，`r/b` 红/蓝，数字键 1–8 编号，`s` 跳过。
2. **防偏**：
   - 预填时**交替用两个模型**（奇偶帧换），任一方都不独占初始值；
   - 其中 **10 帧盲标**（不给预填），用于估计"预填锚定"带来的偏差；
   - 标注者必须逐点确认，不允许全盘回车——在工具里加一道"未移动过任何角点则拒绝保存"的检查（可选严格模式）。
3. 质量：同一帧重复标 3 次（10 帧），算角点标准差；>1.5px 的帧降级为"仅分类/存在性"用途。

## 6. 实验矩阵

> 每个阶段都有"通过条件"，不通过就停在原地，不硬推进。

### S0 冒烟（0.5 人日）

目的：确认 yolo11 这条路径是"能用"的，再谈"好不好"。

步骤：
1. `RMV_DET_MODEL=yolo11 ./build/test_detect tests/data/synth_small_1.png --red --save /tmp/y11.png`，肉眼比对 `/tmp/y11.png` 与 yolov5 的角点是否落在同一块板上、顺序是否 TL/TR/BR/BL。
2. 打印一次原始输出形状与置信度范围：确认 `1x50x8400`、transpose 后行布局、38 列 argmax 落在合理类别。
3. 检查 `RMV_DET_SIZE` 交互：不设 `RMV_DET_SIZE` 时 yolo11 应走 `models/yolo11_640x480.xml` → 缺失 → **回退 640x640 并打印警告**（确认这条回退是可见的，不是静默）。**A/B 期间统一显式设 `RMV_DET_SIZE=640x640`**，避免每次都走一遍失败加载。
4. `./build/bench_detect` 确认 yolo11@640x640 用例能跑。

通过条件：无异常、无 NaN、角点顺序目视正确、回退警告可见。

### S1 无 GT 筛查（0.5 人日）

目的：用 30 分钟找出"一眼假"的问题，避免在标注上白花时间。

步骤：
1. 实现 `tests/ab_detect.cpp`（见 §7.1），对 300 帧候选跑两模型，输出逐帧逐目标 CSV。
2. 看三件事：
   - 检出数逐帧差异（yolo11 系统性少检/多检？集中在某段？）
   - `quad_ok` 率（**不需要 GT，直接暴露 R1**）
   - `detect()` 中位延迟比值（若已 >1.3×，S3 的 640x480 spike 要提前做）
3. 抽 15 帧做叠加图对照组（两模型各画一张），人工扫一遍有没有"框到别的东西"。

通过条件：能给出"哪几帧/哪几类差异最大"的具体清单；若 `quad_ok` < 99%，直接把 H4 标为"确认失败"，进入修复分支（见 §8）。

### S2 精度 A/B（1.5 人日，含标注 1.0）

步骤：
1. 完成 Tier A 100 + Tier B 200 标注（§5.4）。
2. `ab_detect` 跑全量，`ab_report.py` 出表：总表 + 分距离桶 + 分大小/颜色 + 分滚转桶。
3. **H4 专项**：从 Tier A 里取 50 帧，用 `cv2.rotate`/仿射旋转 ±10/±20/±30/±40°（边缘补黑），跑两模型，看 `quad_ok` 与角点误差随角度变化。这一步能直接画出"yolo11 从几度开始崩"的曲线。
4. 失败案例存档：漏检、错号、错大小、`quad_ok=0` 各存 5 张到 `docs/assets/ab_yolo11/`。

产出：`docs/assets/ab_yolo11/metrics.md`（表）+ 曲线图（matplotlib 可选，或直接 Markdown 表）。

通过条件：指标齐全、每个结论都有帧号可查。

### S3 延迟 A/B（0.5 人日）

1. `tests/bench_detect.cpp` 改造：AB 交替段改为 4 项 `{yolov5@640x480, yolov5@512x384, yolov5@640x640, yolo11@640x640}`，**基线显式固定为 `yolov5@640x480`**（现有代码把 `ab_count-1` 当基线，追加 yolo11 会让基线变成 yolo11，必须改）。数组同步放宽到 4。
2. `ab_detect` 的 CSV 里带 pre/infer/decode 三段，报中位/p90。
3. 端到端：`test_camera_live --no-display` 各跑 60s（同场景、同曝光），记录 `fps_cam` 与 `fps_nodisp`。
4. **S3.3 条件分支（yolo11@640x480 变体）**：仅当"精度已过、延迟不过"时启动。
   - 先做 0.5 人日 spike：评估 `tools/make_small_ir.py` 扩展成本（anchor_points 8400→6300、strides 与 DFL reshape 常量、非正方形 letterbox 烘焙）。**结论可以是"成本过高，放弃"**——那也是一个合法结论。
   - 若做出来：用同帧回归验证与 640x640 的一致性（检出数/ID/角点差 ≤ 2px），再重测延迟。

通过条件：比值 + 置信区间；明确写出"是本机 CPU 还是比赛机"的口径。

### S4 下游与实机（0.5 人日）

## 7. 新增/改动的代码

### 7.1 `tests/ab_detect.cpp`（新，核心）

职责：**同一批图，两个模型，逐帧逐目标落 CSV**。不依赖相机，不依赖 GT。

```
mkdir -p tests/results
./build/ab_detect --dir tests/data/ab_yolo11/frames \
                  --config config/camera.yaml \
                  --models yolov5_640x480,yolo11_640x640 \
                  --out tests/results/ab_yolo11.csv
```

> `tests/results/` 只放 CSV 与统计中间产物（单个 CSV 约几十 KB），可以提交，便于别人复跑统计；曲线图与叠加图放 `docs/assets/ab_yolo11/`。

- 直接实例化两个 `ArmorDetectorNet`（不走 `nnDetector` 单例，否则一个进程只能有一个模型）。
- 过滤逻辑与 `armorDetectNn` 完全一致：敌方颜色、`conf>=0.7`、四角在图内。**另外单独记录过滤前的原始检测数**，便于诊断"是模型不行还是后处理砍掉了"。
- 每帧记 `detect()` 总耗时 + 三段拆分耗时；PnP 用 `armor_solve`（`CameraParameters` 从 `config/camera.yaml` 读，`GimbalState` 全零——外参是占位单位阵，所以位姿就落在相机系，两模型口径一致即可），两个模型各自独立的历史（孪生解消歧依赖上一帧）。
- `quad_ok` 自检在工具内算，规则见 §4.2。

CSV 列（一条 = 一个检测；无检测的帧也写一行 `det_idx=-1`）：

```
model,frame,det_idx,color,id,size,conf,x0,y0,x1,y1,x2,y2,x3,y3,
quad_ok,pnp_ok,reproj_px,dist_m,yaw_deg,raw_dets,kept_dets,
detect_ms,pre_ms,infer_ms,decode_ms
```

> 为什么不用现成 `test_batch`：它只打印汇总、无逐帧明细、无 GT 匹配、无法配对；改它会把"验收工具"和"实验工具"搅在一起。新工具更干净，也更容易被评分者复跑。

### 7.2 `tools/ab_extract.py`（新，小）

按 manifest 抽帧、命名、写 `manifest.csv`（源视频、帧号、粗分层标签）。用 `cv2.VideoCapture` 顺序读 + 跳帧（不要 `set(CAP_PROP_POS_FRAMES)` 随机 seek，AVI 上不可靠）。

### 7.3 `tools/label_armor.py`（新）

见 §5.4。~150 行 OpenCV 交互，输出 JSON。只依赖 cv2 + numpy（系统 Python 已有）。

### 7.4 `tools/ab_report.py`（新）

读 CSV + labels → 匹配 → 出 Markdown 表 + bootstrap 置信区间（1000 次重采样）+ McNemar（检出/漏检配对）。只依赖 csv/json/math/random，**不强依赖 numpy**（方便别人跑）。
