### 1.1 我们现状（`student/src/StudentTasks.cpp:800-819`）

```cpp
else if (count >= 2 && fabs(errors[0]-errors[1]) <= 3.0) {
```

`IPPE_DEBUG=1` 实测 11644 条：

```
|z0-z1|       : 中位 1.00 mm  p90 4.0    max 10 mm   → 深度几乎一样，差的是姿态
pick 与最小误差冲突 : 82.5%
```

再看我们还叠了一层 `optimize_yaw`（移植自 sp_vision_25），但实测**开关它没有区别**：

### 1.2 sp_vision_25 的做法（`solver.cpp:54-88, 196-218`）

```cpp
cv::solvePnP(..., rvec, tvec, false, cv::SOLVEPNP_IPPE);   // 单解重载，根本不看孪生解
...
optimize_yaw(armor);

void Solver::optimize_yaw(Armor & armor) const {
  Eigen::Vector3d gimbal_ypr = tools::eulers(R_gimbal2world_, 2, 1, 0);
  constexpr double SEARCH_RANGE = 140;                       // ±70°
  auto yaw0 = tools::limit_rad(gimbal_ypr[0] - SEARCH_RANGE/2*CV_PI/180.0);  // 锚 = 云台朝向
  for (int i = 0; i < SEARCH_RANGE; i++) {                   // 1° 步长
    double yaw = tools::limit_rad(yaw0 + i*CV_PI/180.0);
    auto error = armor_reprojection_error(armor, yaw, (i-SEARCH_RANGE/2)*CV_PI/180.0);
    if (error < min_error) { min_error = error; best_yaw = yaw; }
  }
  armor.yaw_raw = armor.ypr_in_world[0];
  armor.ypr_in_world[0] = best_yaw;
}
```

三个关键点，缺一不可：

1. **保留 tvec，丢掉 PnP 的旋转。** 直接不要那对孪生解。
2. **pitch 硬编码 15°、roll 恒为 0**（`reproject_armor` 里的 `R_armor2world` 只有 yaw∘pitch 两个自由度）。
3. **锚是 `gimbal_ypr[0]`（云台朝向）**，不是 PnP 的 yaw。

### 1.3 我们的移植版错在哪

| 项 | sp_vision_25 | 我们的 `optimizeArmorYaw` |
|---|---|---|
| 锚点 | `gimbal_ypr[0]`（云台朝向，与 PnP 无关） | `basis.yaw0 = atan2(n_y, n_x)`（就是 PnP yaw） |
| pitch | 硬编码 15° | 保留 PnP 量测 pitch（`asin(-n_z)`） |
| roll | 恒为 0（矩阵结构决定） | 保留 PnP 的 `u` 向量 |
| tvec | 保留 | 保留 |

问题在于：孪生解差的正是 **pitch/roll**（深度只差 1mm）。我们保留了从错误解继承来的 pitch/roll，再在一个错误的 pitch/roll 平面里扫 yaw，等于在三维流形上切了一刀，出不了错盆地；而且锚点也被拖进同一个盆地。

### 1.4 实测：六种策略对比（同一份 11644 条检测，同一套关联）

| 策略 | yaw 残差 σ | p90 | p99 | max | \|Δ\|>20° | >30° |
|---|---|---|---|---|---|---|

| S1 最小重投影 | 7.84° | 6.93 | 35.84 | 92.41 | 2.65% | 1.70% |
| **S2 扫描，锚=云台朝向，pitch=15°（sp_vision_25 忠实干法）** | **0.94°** | 1.53 | **3.51** | **7.09** | **0%** | **0%** |
| S2′ 同上但 pitch=0° | 1.36° | 2.25 | 4.80 | 10.11 | 0% | 0% |

## 2. 问题②：半径，三家怎么处理

### 2.1 共同点：没有一家用"同帧双板弦长"在线估半径

| 项目 | 代码证据 | 效果 |
|---|---|---|
| sp_vision_25 | `target.cpp:109-121`，Q 矩阵第 8/9/10 行（r, l, h）**全为 0** | 构造时给个常数，之后 Q=0 → 冻结 |
| rmcs_auto_aim_v2 | `robot.hpp:70-71` `noise_radius_forward = noise_radius_lateral = 1e-8`；`robot.cpp:77` P0 给 `1e-2` | 前几帧收敛，之后随机游走幅度≈0 |
| rm_auto_aim | `tracker.cpp:113-121`「Prevent radius from spreading」，硬钳 `[0.12, 0.40]` | EKF 估但压住不发散 |

三家都把它当**机器人固有几何常数**，不是动态状态。我们的 `updateRadiusFromPairs` + `applySlowRadius` + 20% 分位 + 0.5mm/帧限速，是一个开源里没有对应物的自研通道。

### 2.2 我们的弦长通道为什么必然"呼吸"

已经确认（上一轮）：

- 单板帧 R 完全冻结（`|ΔR| ≡ 0`，0/4184 次写入），R **只在双板帧写**（双板帧的 14.5%）
- 165 帧窗的 20% 分位目标在 **261…355 mm** 之间摆
- 限速 0.5mm/帧 = 82.5mm/s，追不上目标，滞后最多 86mm → 表现为缓慢呼吸

### 2.3 弦长公式里还有一个硬编码偏差

`updateRadiusFromPairs` 用「模型构型」当半角，即假定相邻两板夹角恰为 90°：

```cpp
half_model = 0.5*kPi;      // 对置
half_model = 0.25*kPi;     // 相邻 → sin(45°) = 0.7071
radius = chord / (2.0 * sin(half_model));
```

实测同帧同 id 双板 3534 对，两板法向夹角：

| 用的 yaw | Δψ 中位 | Δψ std |
|---|---|---|
| 现状（`n_y` 规则） | **104.4°** | 9.0° |
| S2 扫描（pitch=15°） | **84.5°** | 4.3° |

`R = chord / (2 sin(Δψ/2))`，Δψ 从 90° 偏 14° 就会让 R 偏 **−11%**（sin(52.2°)=0.790 vs sin(45°)=0.707）。弦长中位 423.7mm 时：

```
假定 90°（现状）  → R = 299.6 mm
用实测 104.4°     → R = 268.0 mm
用 S2 的 84.5°    → R = 318.0 mm
```

也就是说，**"R 该是多少"这件事本身就带着 ±25mm 的系统性不确定，量级和观察到的呼吸完全一致**。20% 低分位恰好把这个偏差往下压了一点（277–284mm），看起来"差不多对"，实际上是两处误差互相抵消。

> 这一条把问题①和问题②接上了：yaw 估不准 → 板间距估成 104° → 弦长公式按 90° 换算 → R 系统性偏 ±11%。

## 3. 问题③：单板关联，sp_vision_25 怎么处理

`target.cpp:138-185`：

```cpp
void Target::update(const Armor & armor) {
  // 1) 为 4 个槽各算一个预测 (ypd, angle)
  // 2) 按预测距离 ypd[2] 排序，只取最近 3 个槽
  // 3) 角度误差 = |板 yaw − 槽预测 yaw| + |板方位角 − 槽预测方位角|，取 argmin
  for (int i = 0; i < 3; i++) {
    auto angle_error = std::abs(limit_rad(armor.ypr_in_world[0] - xyza[3]))
                     + std::abs(limit_rad(armor.ypd_in_world[0] - ypd[0]));
    if (|angle_error| < |min_angle_error|) { id = ...; min_angle_error = angle_error; }
  }
  if (id != 0) jumped = true;
  update_ypda(armor, id);      // 无条件更新，没有 NIS 门，没有 realign
}
```

对照我们的做法：NIS 门 → 连续 3 帧拒绝 → `single_plate_realign` → `rotatePhase` 转 180° + `shiftCenter`。实测 7 次 realign 全部发生在 `n_id=1` 帧、φ 一律翻 ~180°、触发前 NIS 高达 339–1472。

sp_vision_25 用「**先在最近 3 个槽里 argmin，再无条件更新**」代替了整条拒绝-重对齐链。槽位错了顶多是一次带偏的更新，不会把整车的 φ 翻 180°。

## 4. 单一整合方案（按依赖顺序，一次改完）

### 改 1 —— `student/src/StudentTasks.cpp`：yaw 求解换成 sp_vision_25 的干法

- 删掉 `solvePoseForTrack` 里的孪生解消歧分支（`normals[0][1] <= normals[1][1]`），改成只取 `solvePnP` 单解重载拿 tvec。
- 重写 `optimizeArmorYaw`：pitch **硬编码常量**（本素材实测 15°，做成 `armor_pitch_deg` 配置项，默认 15），**roll 恒 0**，锚点换成**云台朝向**（`gimbal_yaw`，不是 PnP yaw），±70°/1° 扫描 + 0.1° 抛光。
- 保留 `OPTIMIZE_YAW_PITCH` 环境变量做实验，但默认值改为 15 而不是「保留量测值」。
- 预期：yaw σ 5.74° → **0.94°**，>30° 跳变 2.43% → **0%**，max 47.5° → **7.1°**。

### 改 2 —— `student/src/RotatingArmorTracker.cpp`：半径从"在线估计"改成"一次性收敛后冻结"

- `applySlowRadius` 里删掉 20% 分位 + 限速的组合，改成：
  - 弦长的半角用**实测 Δψ**（`dpsi > 阈值` 时 `half = dpsi/2`），不再假定 90°；
  - `radius_track_m_` 用低通收敛到该值；
  - 收敛判定（连续 N 帧 |R−target| < 3mm 或样本数 ≥ M）之后**置位 `radius_frozen_`，此后不再写**，等价于 sp_vision_25 的 `Q(8,8)=0`。
- 新目标锁定时清 `radius_frozen_`（每台车的 R 是常数，不是每帧的变量）。
- 预期：R 从 269–298mm 的随机游走变成一次性收敛，之后是一条水平线。

### 改 3 —— 单板关联换成 argmin，删掉拒绝-重对齐链

- 用 sp_vision_25 的 `update()` 替换现有的 NIS 门 + `single_plate_realign`：在所有槽里按「角度误差 + 方位误差」argmin（限制最近 3 个槽），然后无条件更新。
- `single_plate_realign` 的 `rotatePhase` 直接删掉（保留 `shiftCenter` 仅供参考或一并删）。
- 预期：7 次 180° 翻转消失，四个模型板不再抽搐。

### 风险与边界

- **改 1 依赖"板确实上倾"这个物理前提。** 本素材实测 14.2±4.9°，与 RM 实车一致；若某台车确实是竖直板，用 `armor_pitch_deg=0` 即可（实测 σ 1.36°，仍远好于现状）。
- **改 2 让 R 变成半静态量。** 换车/换道具必须触发重新收敛，否则会带着上一台车的 R。需要在换 `target_id` 时清冻结标志。
- **改 3 去掉了 NIS 门。** 单帧离群观测会直接进更新，靠 `R_dig` 自适应降权吸收（sp_vision_25 也是这么做的：`R_dig[2] = log(|Δangle|+1)+1`，斜视角时自动放大距离的方差）。

### 6.1 改 ①（yaw 求解）—— 已落地，达标

落地文件 `student/src/StudentTasks.cpp`：`solvePoseForTrack` 单解 IPPE 只留平移，
`optimizeArmorYaw` 用 (yaw, pitch) 两自由度重建、锚点固定 180°、pitch 15°、roll 恒 0，
±70°/1° 扫描 + ±0.5°/0.1° 抛光。

移植过程里踩了三个**写在文档里比代码本身更重要**的坑：

| 坑 | 现象 | 根因 |
|---|---|---|
| 锚点用板方位角 | σ 7.53° | 四板车的板法向与板方位差 90°，锚错就是窗口整体偏 90° |
| 三列按"z 朝向相机"构造 | 精修**完全空转**，σ 停在 PnP 基线 | (x 右, y 下) 的右手系里 z 只能背离相机。取 +n 使 det(R)=-1，四角重投影成交叉四边形，代价中位 **69.7px**，6px 门禁每帧拒绝、每帧 `return` 回退 PnP 原解。验证：11644 帧里"z 朝相机"0 帧胜出、"z 背离相机"11644/11644 胜出（代价中位 1.23px） |
| 锚点写成 0° | 扫到窗口边界 yaw=-71.5°、err 75px | 扫描参数是"朝相机那一侧法向"的方位角，与 z 轴方位差 180°，锚点必须是 180° 不是 0° |

最终构造（三列，云台系，x 右 / y 下 / z 背离相机，x×y=z）：
```
x = (-sin y,  cos y,      0)
y = ( sp·cos y, sp·sin y, -cp)
z = (-cp·cos y,-cp·sin y, -sp)     // z 的方位角 = yaw + 180°
```
下游本来就有"法向必须指向相机（n·p<0）"的归一化（StudentTasks.cpp 里那条 `if`），
所以输出背离相机的 z 不需要额外补偿，翻转是确定性的、不会抖。

### 6.2 改 ②（半径）—— 已落地，但**改了方案**

原设想是"弦长半角改用实测 Δψ + 收敛后冻结"。实测**前半句是错的，已撤回**：

- 相邻板 Δψ 实测 = **84.30° 中位、σ 2.60°**（p10~p90 = 80.6~86.7，n=3515 帧）。
  系统偏离 90° 是真的，但 2.6° 散布代进 `1/sin()` 后收益为负：
  同一段素材逐帧半径 σ 从 **0.0298 涨到 0.0351**，`|ΔR|` 中位 4.0→4.8mm。
- 所以三处弦长公式（`updateBodyFromPair` / `updateRadiusFromPairs` / `noteChordRadius`）
  **继续用模型构型的 90°/180°**，并把这个反直觉的实测结论写进了代码注释。

保留的后半句"收敛后冻结"才是真正的解药。半径的"呼吸"其实是**秒级慢漂**：
`|ΔR|` 逐帧中位是 0，但 moveandrotate.avi 里 R 在 0.272~0.299 之间来回漂。
机制就是单板观测只给"圆心在板心 + R·n 这条射线上"，R 与车心强耦合，
滤波可以拿 R 换车心。三家开源全都不在线学半径（sp_vision_25 Q[8..10]=0、
rmcs noise_radius_*=1e-8、rm_auto_aim 硬钳），做法一致。

实现：`applySlowRadius()` 加一处冻结闸门（弦长、圆拟合、批拟合三条写入路径
都从这里进，一处就够），新配置 `radius_freeze_residual_ratio=0.01`、
`radius_freeze_confirm=5`，`reset()` 跨锁清零。

冻结判据**必须是残差不是步长**，这是第二次踩坑：
| 判据 | 结果 |
|---|---|
| 步长 < 3mm 连续 15 次 | 低通 alpha=0.06，正常靠拢期步长本来就只有几毫米 → **把 R 误锁在 0.207**（真值 0.283） |
| 写满 80 次就冻结 | 80 次只走到一半 → **锁在 0.240** |
| **残差 < 1%·R 连续 5 次（采用）** | 帧 520 收敛到 0.285 后冻结，**后 3/4 段漂移 0.0mm**（改前 33.2mm） |

### 6.3 改 ③（单板 realign 折叠 180°）—— 做了 A/B，**收益不单调，已撤回**

"单板关联改 argmin 槽位"这条**现网代码本来就是这样**：`associateAndUpdate` 对
(observation, slot) 全枚举取 score 最小，score 里还带了法向差和方位差两项。

"删掉 realign 的 180° 翻转"实际去试了：把 `delta_theta` 折进 (-period/2, period/2]，
理由是四板模型对 period 整数倍旋转完全对称，转整槽只是槽位换名，
留着会让 aim_slot 指到对面那块板上。结果：

| 素材 | 不折叠 | 折叠 |
|---|---|---|
| middlespeed | >30° 相位跳变 21 次（含 5 次 ~180°） | **14 次，~180° 全消**；slot 切换 621→528 |
| highspeed | >30° 跳变 **3 次**、realign **4 次** | >30° 跳变 **21 次**、realign **47 次** |

原因：折叠后 `rotatePhase` 只挪不到一个槽位，紧跟着的 `shiftCenter` 就必须
把车心朝观测板方向硬拽最多 2R 来补齐角度差，反而把车心拽飞、missed 变多、
realign 反复触发。**改的是错的变量**——要消"瞄准圈跳 180°"应该在折叠后
重选 aim_slot，而不是压 `delta_theta`。已撤回并留下注释。

### 6.5 后续建议

- realign 的"跳 180°"要另开一轮：折叠 delta_theta **并且**重选 aim_slot，
  只改其中一半就是 highspeed 上那样的反效果。
- 半径冻结依赖"换车走 reset()"，真机换车不换 id 时需要确认 dropTarget 会被触发。
- stable.avi 每帧只有 1 块板，R 恒为 0.2000（无弦长可用），所以"单板半径晃"在
  本 harness 里复现不出来；真机上若还看到晃动，要看是不是 R 的**显示源**
  用了别的量（例如锁定前的拟合半径），而不是 EKF 状态里的 R。
